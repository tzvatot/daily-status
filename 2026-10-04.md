# Daily Status - 2026-10-04

## Accomplishments

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — SNO environment root cause investigation:** Identified why the karim04 blade SNO environment had been broken since Oct 1: the fulfillment-service image uses a floating tag that advanced past the Helm chart's compatibility window, introducing mandatory runtime dependencies the chart does not supply. Documented the root cause and recommended remediation (pin the image to the last known-good digest before reinstalling, or wait for a matching chart update) in the team runbook.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — Secondary blade CaaS assessment and environment preparation:** Evaluated a secondary blade for CaaS suitability, confirmed it lacked the required agent infrastructure, and ran the full setup workflow to register a discovery agent and bring the environment to a state ready for tenant-cluster provisioning. Actual provisioning testing remains pending.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — Replacement CaaS test environment build-out (in progress):** As an alternative to the broken karim04 environment, cleaned up stale virtual machines and containers to recover disk space, installed and configured cluster-tool, booted a fresh SNO clone with all cluster operators healthy, and completed the virtual bare-metal host layer. OSAC image builds are currently running; remaining steps — loading images, chart installation, AAP and DNS configuration, and the full E2E run — are pending.

- **Worktree cleanup and tooling improvements:** Removed nine stale Git worktrees associated with merged or closed work, extended the workspace cleanup script to cover all relevant repositories, built and pushed a fresh operator image for active E2E use, and authored a troubleshooting reference document summarizing the issues encountered during the past week of blade environment setup.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS test failure root cause identified:** Investigated a provisioning test failure on the secondary blade and traced it to a stale allocation claim left on the only available agent by a prior failed order, causing the operator to correctly exclude it from capacity for new orders. Cleaned the failed orders; releasing the stale claim and rerunning the test remain to be done.

## Risks & Challenges

- **karim04 blade environment is broken and cannot be used for E2E testing** — a floating fulfillment-service image tag moved ahead of the Helm chart between Sep 29 and Oct 1, introducing unmet runtime dependencies. Recommended fix is to pin the image to the last known-good digest before reinstalling, or wait for a chart update. Tracked under [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441).
- The replacement cluster-tool environment is still in the image build and install phase; E2E validation has not yet started.
- The secondary blade's CaaS test is blocked by a stale agent allocation from a prior failed order; the cleanup and rerun are pending.

## Key Effort

Building a replacement CaaS E2E test environment on the karim04 blade using cluster-tool, after the original SNO environment was rendered unusable by a fulfillment-service image and Helm chart incompatibility.
