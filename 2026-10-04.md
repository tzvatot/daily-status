# Daily Status - 2026-10-04

## Accomplishments

- **Diagnosed and declared the karim04 blade broken** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): root cause is a floating `fulfillment-service` image tag that drifted ahead of the Helm chart, introducing new CORS and Kafka requirements the chart does not satisfy. Documented the workaround in the runbook and recommended pinning to the last-known-good image digest before reinstalling.

- **Assessed and prepared a secondary SNO host for CaaS provisioning**: confirmed the host was healthy but had no CaaS agent infrastructure in place; ran the full setup workflow to create the required resources, resolved a network routing issue that was blocking agent discovery, and brought the environment to the point where a CaaS agent is registered, labeled, and approved. Actual tenant-cluster provisioning remains to be tested.

- **Progressed the cluster-tool CaaS e2e environment build on the karim04 blade** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): cleaned up stale VMs and containers, freeing ~313 GiB of storage; installed and configured cluster-tool; booted a fresh SNO clone with all cluster operator checks passing; built and loaded all component images from a branch checkout (fulfillment-service, operator, AAP execution environment, bare-metal operator, metering, and echo adapter). The OSAC Helm chart install is currently blocked because Kafka-dependent resources remain active even when Kafka is disabled in values; reached out to the team on Slack for guidance on the correct path forward.

- **Cleaned up stale development worktrees and improved tooling**: removed 8 merged or closed worktrees from the workspace, updated the cleanup script to cover all workspace directories, built and pushed an operator image from the intermediate-events branch, and created a management-level summary document covering all issues encountered during five days of blade environment setup.

- **Investigated and identified root cause of CaaS e2e test failure** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): a prior failed test order left a stale namespace and a stale claim label on the only registered CaaS agent, causing subsequent provisioning attempts to report zero available capacity. Added a 60-minute ClusterOrder timeout with automated cleanup and manually cleared the failed orders. Cleaning the stale namespace and re-registering the agent to unblock the lifecycle test is still pending.

## Risks & Challenges

- **karim04 blade is broken and unsuitable for e2e testing**: the floating `fulfillment-service` image tag drifted ahead of the Helm chart, and post-install patches cannot be applied within a Helm install cycle. Must pin to a known-good image digest before reinstalling.
- **OSAC Helm chart install is blocked**: Kafka-dependent resources remain mounted even with Kafka disabled, leaving fulfillment pods unready. Awaiting team guidance on whether to enable Kafka or adjust the chart.
- **CaaS e2e test is blocked by a stale agent allocation**: the only registered agent carries a claim label from a previous failed order and cannot be reused until the stale namespace is cleaned and the agent is re-registered.

## Key Effort

Rebuilding the CaaS end-to-end test environment from scratch on the karim04 blade using cluster-tool, while in parallel diagnosing failures on a secondary host and advancing [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) e2e validation.
