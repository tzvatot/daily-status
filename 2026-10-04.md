Environment has been cleaned; blocker is the VM boot-order causing the agent to reboot into the discovery image instead of the installed disk.

Currently blocked on making Agent NTP and DNS configuration persist across environment rebuilds; environment and logs are preserved for diagnosis.

## Risks & Challenges

- **karim04 blade (10.6.76.209) original environment is broken** — the floating fulfillment-service image moved ahead of the Helm chart; the old environment is unusable until reinstalled with a pinned compatible image. A cluster-tool replacement environment is now in use but also blocked (see below).
- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) worker VM boot-order loop (both blades)** — the CaaS worker agent stalls at 55% after installation because the VM reboots into the discovery image rather than the installed disk. This prevents the worker from joining the hosted cluster and blocks the E2E test from reaching any assertions. A boot-order fix exists as a local uncommitted experiment but has not yet been validated on a clean agent.
