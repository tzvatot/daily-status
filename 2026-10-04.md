# Daily Status - 2026-10-04

## Accomplishments

- Investigated the root cause of the broken karim04 blade environment for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441): a floating fulfillment-service image tag had advanced ahead of what the Helm chart supports, introducing mandatory Kafka and CORS requirements the chart does not configure. Documented a pinned-image workaround in the runbook and declared the environment unsuitable for testing in its current state.

- Assessed a second blade environment for CaaS suitability: confirmed the host was healthy but missing all CaaS provisioning prerequisites. Ran the standard CaaS agent setup workflow, resolved an assisted-service routing mismatch, and successfully registered and approved a CaaS agent. The environment is prepared for provisioning; actual tenant-cluster creation has not yet been validated.

- Built a new CaaS test environment on the karim04 blade using cluster-tool for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441): cloned an SNO instance, worked around broken RHEL entitlements using standalone package alternatives, resolved DNS and networking blockers, and brought the cluster to a healthy state with all operators ready.

- Resolved Kafka installation blockers and completed the full OSAC component installation on the cluster-tool CaaS node: determined that the current fulfillment image requires Kafka and the previously documented Kafka-disabled workaround is no longer valid, re-enabled Kafka, and confirmed all fulfillment pods and the AAP bootstrap job reached a healthy state.

- Built and loaded all six OSAC component images from the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) branch into the cluster-tool CaaS node, covering fulfillment-service, the operator, the AAP execution environment, bare-metal operator, metering, and echo adapter.

- Registered the required host type, relabeled virtual bare-metal hosts, provisioned a CaaS agent, and resolved assisted-service validation blockers around hosted-cluster DNS resolution and NTP reachability to prepare the cluster-tool environment for end-to-end testing. Also repaired a stale AAP project state that was preventing job template execution.

- Ran the CaaS lifecycle E2E test on the cluster-tool environment: a cluster order was created and hosted cluster provisioning began, but the agent completed Assisted Installer installation and then failed to boot from the installed disk, leaving the worker unable to join. The test was stopped and cleaned; the VM boot-loop is the current definitive blocker on this environment.

- Ran the CaaS lifecycle E2E test on the second blade environment: a cluster order was created and the control plane reached a created state, but the worker agent failed DNS and NTP validation during provisioning due to persistent misconfiguration of freshly registered agents. The test is paused pending a durable fix for NTP and hosted-cluster DNS configuration.

- Cleaned up stale merged and closed worktrees from the OSAC workspace, updated the worktree cleanup script to cover additional repositories, built and pushed an operator image from the intermediate-events branch, and created a management-level summary of blade environment issues encountered over the past week of setup work.

## Risks & Challenges

- Both CaaS test environments are currently blocked before the worker node can join, meaning the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) lifecycle E2E test cannot reach its assertion phase: the cluster-tool environment has a VM boot-loop where the agent re-enters the discovery ISO instead of booting the installed disk after Assisted Installer completes; the second blade environment has a recurring NTP and hosted-cluster DNS misconfiguration that fails agent validation on every fresh agent registration.
- The NTP and hosted-cluster DNS fix on the second blade environment is a live patch that is lost on every environment rebuild; it must be made durable before testing can be reliable.
- The karim04 blade's original environment remains broken due to the floating image tag issue and requires either a pinned image or a chart update before it can be used independently.

## Key Effort

Resolving cascading CaaS test infrastructure blockers across two blade environments in order to execute the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) lifecycle E2E test, with both environments now blocked at the worker-node join stage.
