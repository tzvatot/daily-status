# Daily Status - 2026-10-04

## Accomplishments

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — Blade environment root cause identified:** Determined that the karim04 blade SNO environment broke because the `fulfillment-service` image uses a floating tag that moved ahead of the Helm chart between a working deployment and a broken one, causing cascading CORS and Kafka initialization failures. Updated the runbook with the recommended remediation path (pin the image digest or wait for chart update).

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS agent environment set up on alternate blade:** Assessed a second blade for CaaS suitability, performed the full CaaS agent setup (host type, networking, discovery image boot, agent registration and approval), and worked around a DNS routing issue caused by an unroutable internal address. The environment is prepared for CaaS provisioning; actual tenant-cluster provisioning has not yet been validated.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — Cluster-tool CaaS test environment built on karim04:** Cleaned all stale virtual environments and freed storage on karim04, stood up a fresh cluster-tool–managed CaaS SNO clone, and worked around broken RHEL entitlements using standalone packages. Built and loaded all six OSAC component images locally. Resolved a Kafka configuration blocker — the runbook workaround of disabling Kafka is no longer valid for the current image; leaving Kafka enabled with the in-cluster broker is the correct approach. OSAC Helm release deployed and AAP bootstrap completed successfully, leaving the environment ready for E2E testing.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — First CaaS lifecycle E2E test executed on cluster-tool environment:** Ran the CaaS lifecycle E2E test against the cluster-tool environment. Pytest collected and entered the real create-cluster path but the test failed at the initial CLI call with a non-zero exit before any ClusterOrder was created. The exact error was not captured because the test runner swallowed subprocess stderr. Next step is to reproduce the CLI call directly to isolate the failure.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS test retries and blockers investigated on alternate blade:** Diagnosed and worked around three successive CaaS test failures: (1) a stale agent allocation from a previous failed order that prevented the agent from being available for new provisioning; (2) a worker VM that repeatedly booted the discovery image instead of the installed disk due to libvirt persisting the wrong boot order; (3) an NTP source configuration lost after an InfraEnv rebuild, causing the worker to fail NTP and API validation. Cleaned failed orders and their lingering resources across multiple retries. The agent was re-registered and re-approved; retry 3 reached the control-plane-available stage and is under observation.

- **Workspace and tooling cleanup:** Removed 8 merged or closed worktrees from the workspace, extended the worktree cleanup script to cover the full workspace (previously only covered a subset), built and pushed an operator image from the intermediate-events branch to the team registry, and wrote a management-level summary documenting all environment issues encountered across 5 days of blade setup.

- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — E2E test on cluster-tool environment is blocked** by an undiagnosed CLI failure (exit status 1, no ClusterOrder created). Root cause is unknown until CLI stderr is captured.
- **[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS agent environment on alternate blade remains fragile:** the boot-order fix is an uncommitted local experiment not yet validated on a fresh agent registration, and the NTP source fix is a live patch that will be lost on the next environment rebuild.
