# Daily Status - 2026-10-04

## Accomplishments

- Investigated and documented the root cause of the broken karim04 blade SNO environment for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441): the `fulfillment-service` floating image tag moved ahead of the Helm chart between deployments, creating incompatible Kafka and CORS dependency requirements; documented the recommended fix (pin to a known-good image digest or await a chart update) in the runbook
- Assessed a second blade environment for CaaS suitability; ran the full CaaS agent setup workflow, worked around a network routing issue for the Assisted Installer service, and successfully registered and approved a worker Agent, leaving the environment ready for tenant-cluster provisioning testing
- Rebuilt the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) e2e test environment on karim04 using cluster-tool: cleaned up stale virtual machines and containers to reclaim storage, worked around RHEL entitlement issues using standalone packages, configured the full infrastructure stack (cluster-tool, libvirt, HAProxy, DNS), booted a fresh SNO clone, built and loaded all six OSAC component images from the feature branch, and — with Slack guidance confirming Kafka is now mandatory — resolved the Helm install blockers; the OSAC Helm chart deployed successfully and AAP bootstrap completed
- Set up the virtual BMH layer, registered the worker HostType and a CaaS Agent, and resolved DNS and NTP validation failures; ran the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) lifecycle e2e test on the cluster-tool environment, which reached real HostedCluster provisioning but is blocked by the worker Agent VM booting the discovery ISO instead of the installed disk after Assisted Installer completes — worker join cannot complete, preventing the test from reaching its event assertions
- Ran additional [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) test retries on the second blade; the latest attempt reached HostedCluster control-plane creation, but the worker Agent failed NTP and hosted-cluster DNS validations, blocking worker join; diagnosed that NTP sources and hosted-domain DNS entries are not persisting across Agent re-registrations
- Cleaned up eight merged and closed feature worktrees from the OSAC workspace, updated the workspace cleanup tooling to scan all worktrees automatically, built and pushed an updated operator image for the intermediate-events branch, and created a management summary documenting all blade environment issues encountered during the past week's setup effort

## Risks & Challenges

- **karim04 blade environment is broken** — the `fulfillment-service` floating image tag diverged from the Helm chart; the environment should not be used for e2e testing until reinstalled with a pinned image version or an updated chart
- **CaaS worker boot loop blocks [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)** — on both test blades, the worker Agent VM boots the discovery ISO instead of the installed disk after Assisted Installer completes, preventing worker join and blocking the lifecycle test from reaching its event assertions; a boot-order workaround is identified but has not yet produced a successful test pass
- **NTP and hosted-cluster DNS configuration not persisting** — fresh Agent registrations lose the required NTP source and hosted-domain DNS entries, causing recurring validation failures on every environment rebuild; a permanent fix in the setup scripts is still pending

## Key Effort
Focused on unblocking the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) CaaS lifecycle e2e test by rebuilding the karim04 test environment from scratch with cluster-tool and resolving a series of installation, Kafka, DNS, and NTP blockers across two blade environments, with the remaining blocker being a CaaS worker VM boot-loop that prevents worker join and test assertion execution.
