# Daily Status - 2026-10-04

## Accomplishments

- Investigated and documented the root cause of the broken karim04 blade ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): the fulfillment-service image advanced ahead of its Helm chart, introducing mandatory CORS and Kafka dependencies the chart does not supply; updated the environment runbook to reflect this and mark the previously documented Kafka-disabled workaround as invalid for the current image
- Set up Dan's blade (10.6.76.208) as a secondary CaaS test environment: assessed hardware and OpenShift state, ran the agent setup workflow, registered and approved a CaaS discovery agent; environment is prepared for tenant-cluster provisioning but provisioning has not yet been validated
- Rebuilt the karim04 blade (10.6.76.209) from scratch using cluster-tool ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): removed stale VMs and containers freeing significant disk space, installed cluster-tool, cloned an SNO base cluster, and resolved multiple sequential blockers including RHEL entitlement issues, missing tooling, and DNS/network misconfigurations
- Built and loaded all six OSAC component images from the OSAC-4441 branch into the cluster-tool SNO environment
- Achieved a healthy OSAC deployment on the cluster-tool environment with Kafka enabled, all pods ready, and AAP bootstrap complete — after determining that the current fulfillment image unconditionally requires Kafka
- Attempted the CaaS lifecycle E2E test ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) on the cluster-tool environment: resolved sequential blockers including missing HostType registration, incorrect BMH labels, absent CaaS agent, hosted-cluster DNS/NTP validation failures, and a stale AAP project revision; the final attempt reached real HostedCluster provisioning but the worker agent entered a reboot loop at 55% installation progress; test did not achieve a pass result and the test order was force-cleaned
- Ran multiple CaaS lifecycle test retries on Dan's blade ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): resolved stale agent claim allocation, worker VM boot-order misconfiguration (discovery ISO booting instead of installed disk), and NTP/API validation failures across several attempts; the latest run reached control-plane provisioning but the worker agent is currently failing hosted-cluster DNS and NTP reachability validation, blocking worker join and test completion
- Added a ClusterOrder ready timeout with automatic cleanup to prevent test runs from stalling indefinitely
- Cleaned up merged and closed worktrees from the OSAC workspace and extended the worktree cleanup script to scan all workspace directories
- Built and pushed a new operator image from the intermediate-events branch to support ongoing test work
- Documented all blade environment setup issues encountered over the past week in a management summary

## Risks & Challenges

- karim04 blade (10.6.76.209) is broken and should not be used for e2e testing until reinstalled with a pinned, chart-compatible fulfillment-service image
- The CaaS lifecycle E2E test ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) is blocked on both test environments: on the cluster-tool environment the worker agent enters a reboot loop after installation; on Dan's blade the fresh agent is failing hosted-cluster DNS and NTP reachability validation during the provisioning phase
- The worker VM boot-order fix (boot from installed disk rather than discovery ISO) has not been validated end-to-end and has not been merged into the agent setup script; the NTP source configuration for the CaaS agent is also not yet persisted and will be lost on the next environment rebuild

Advancing the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) CaaS lifecycle E2E test across two blade environments, resolving numerous sequential infrastructure blockers to reach real HostedCluster provisioning, while remaining blocked by worker agent reboot and DNS/NTP validation failures that prevent test completion.
