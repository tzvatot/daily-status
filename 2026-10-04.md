# Daily Status - 2026-10-04

## Accomplishments

**[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS lifecycle e2e environment rebuild and test execution (blade 10.6.76.209)**

- Diagnosed why the previous SNO install on the karim04 blade was broken: the fulfillment image had drifted ahead of the Helm chart, introducing new mandatory configuration the chart did not set; documented root cause and remediation in the team runbook
- Cleaned up the blade (removed stale virtual machines, freed ~313 GiB of storage) and installed the cluster-tool toolchain despite a broken RHEL subscription, working around missing packages with standalone RPM extraction
- Bootstrapped a fresh SNO cluster clone using cluster-tool, configured networking and DNS, deployed OSAC infrastructure dependencies, and built and loaded locally customized images for all OSAC components
- Resolved a Kafka installation blocker: confirmed with the team that Kafka is now mandatory for fulfillment; re-ran the installation with Kafka enabled and brought all fulfillment pods, the AAP bootstrap, and the OSAC operator to Ready state
- Set up CaaS agent prerequisites: registered the required host type, relabeled the virtual bare-metal hosts, provisioned and approved the discovery agent, and fixed DNS and NTP validation failures that were blocking agent registration
- Fixed a stale AAP project revision failure caused by an SNO network disruption that prevented provisioning job templates from executing
- Ran the CaaS lifecycle e2e test; provisioning advanced through control-plane creation and agent installation but stalled when the agent VM rebooted into the discovery ISO instead of the installed disk, preventing the worker from joining the cluster and the test from reaching its event-assertion phase

**[OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — CaaS lifecycle e2e test retries (blade 10.6.76.208)**

- Ran multiple e2e test iterations, each blocked by a distinct infrastructure issue: stale agent ownership from a prior failed order, agent VM boot-order causing repeated reboot into the discovery ISO rather than the installed disk, and NTP/hosted-cluster DNS validation failures on fresh agent registration
- Applied a live NTP fix to the agent's infrastructure configuration and identified that the fix must be persisted in the environment setup scripts to survive environment rebuilds
- Cleaned up stale test resources (orders, namespaces, finalizers, stale agent registrations) after each failed run to restore a clean state
- Current blocker: the fresh agent's NTP and hosted-cluster DNS configuration must be made persistent in the discovery setup before the lifecycle test can proceed; confirmed that pre-creating a tenant cluster is not an acceptable workaround — the test must drive the full create-and-deprovision lifecycle

**Workspace and tooling maintenance**
- Removed 8 merged or closed git worktrees from the OSAC workspace and updated the automated cleanup script to include the OSAC workspace going forward
- Built and pushed a custom operator image from the intermediate-events branch to support ongoing testing
- Authored a management-level troubleshooting summary documenting the 12 significant issues encountered during five days of blade environment setup

## Risks & Challenges

- **karim04 blade (10.6.76.209) SNO environment is broken** — the fulfillment image has drifted ahead of the Helm chart; do not use for e2e testing until reinstalled with a pinned or compatible fulfillment image
- **CaaS agent VM boot-order loop (both blades)** — after Assisted Installer completes installation, the agent VM reboots into the discovery ISO instead of the installed disk, preventing the worker from joining and blocking test completion; a disk-only boot workaround has been applied but has not yet produced a successful agent reboot
- **Persistent NTP/DNS configuration gap (blade 10.6.76.208)** — the NTP source and hosted-cluster DNS entries required for agent validation are applied as live fixes but are not persisted in the environment setup scripts, so they are lost on every environment rebuild; this must be resolved before the lifecycle test can succeed

## Key Effort

Driving the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) CaaS lifecycle e2e test to first execution across two blade environments, resolving installation, tooling, Kafka, DNS/NTP, and agent provisioning blockers, with the remaining obstacle being a CaaS agent VM boot-order issue that prevents the worker node from joining and the test from completing.
