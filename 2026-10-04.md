# Daily Status - 2026-10-04

## Accomplishments

- Investigated and documented the root cause of the broken CaaS test environment on the karim04 blade ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): a floating fulfillment-service image tag advanced ahead of the Helm chart, causing CORS and Kafka dependency failures; documented the recommended fix (pinning the image to a known-good digest) and updated the runbook

- Assessed a second blade for CaaS suitability, ran the full CaaS agent setup workflow, worked around an assisted-service routing issue, and registered and approved a discovery agent — second blade prepared for CaaS provisioning

- Built a fresh cluster-tool CaaS test environment on karim04 to replace the broken SNO environment: cleaned stale VMs and containers (recovering ~313 GiB of storage), installed cluster-tool, worked around broken RHEL entitlement using standalone packages, booted a new SNO clone with all cluster operators passing, and deployed OSAC infrastructure

- Built and loaded all six OSAC component images into the cluster-tool environment; resolved an installation blocker after Slack guidance confirmed Kafka is now mandatory — re-enabling Kafka caused the OSAC Helm release to reach deployed status and AAP bootstrap to complete successfully

- Resolved a sequence of environment blockers on the cluster-tool environment to reach real ClusterOrder provisioning: missing host type registration, bare-metal host labeling, CaaS agent setup, hosted-cluster DNS validation, NTP validation, and a stale AAP project revision; ClusterOrder reached control plane provisioning but the worker agent is stuck in a post-installation boot loop, preventing test completion ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441))

- On the second blade, ran multiple CaaS lifecycle test retries; diagnosed and applied workarounds for stale agent allocation, VM boot-order (agent rebooting from discovery ISO instead of installed disk), NTP source configuration, and hosted-cluster DNS validation; latest run reached `ControlPlaneCreated` but is blocked by NTP and DNS configuration not persisting in fresh agent discovery, preventing the worker from passing validations and joining ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441))

- Removed stale merged and closed worktrees from the OSAC workspace, updated the worktree cleanup script to scan all worktrees instead of only top-level repos, built and pushed an operator image from the intermediate-events branch, and created a management-level troubleshooting summary covering all environment issues encountered over the past week

## Risks & Challenges

- **Both CaaS test environments are blocked on worker node join, preventing [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) E2E test completion:**
  - karim04 cluster-tool environment: the worker agent enters a post-installation boot loop (boots into the discovery ISO instead of the installed disk), so the worker never joins and the test cannot reach its lifecycle-event assertions
  - Second blade: fresh agent discovery configuration does not include the required NTP sources or hosted-cluster DNS entries, causing validation failures that prevent the agent from being claimed by the NodePool
- NTP and hosted-cluster DNS fixes applied live are not persisted through agent re-registrations, requiring repeated manual intervention after every environment rebuild

## Key Effort

Driving [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) CaaS lifecycle E2E test execution across two blade environments, resolving a full chain of infrastructure blockers (Kafka, host type registration, DNS/NTP validation, AAP project state), now blocked on worker node boot and agent validation failures that prevent cluster creation from completing.
