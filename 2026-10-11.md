# Daily Status - 2026-10-11

## Accomplishments
- **[OSAC-5508](https://redhat.atlassian.net/browse/OSAC-5508) – CI Netris certificate validation:** Disabled certificate validation in CI Helm values and rebased [osac#1475](https://github.com/osac-project/osac/pull/1475) onto latest main. Awaiting refreshed CI integration-test results; VMaaS E2E has failures under investigation.
- **Quarterly connection:** Completed and submitted quarterly connection.
- **[OSAC-5972](https://redhat.atlassian.net/browse/OSAC-5972) – Netris CA validation matrix:** Ran a full end-to-end validation matrix for [osac#1520](https://github.com/osac-project/osac/pull/1520), covering all certificate validation scenarios: HTTPS with validation disabled, HTTP with validation disabled, HTTP with validation enabled, HTTPS with validation enabled and no CA (expected failure), HTTPS with wrong certificate SAN (expected failure), DHCP/IPAM lookup with a provisioned host, full BMaaS/BareMetalHost provisioning, and positive HTTPS with a trusted private CA and matching SAN. All positive and negative cases produced the expected results.
- **[OSAC-5972](https://redhat.atlassian.net/browse/OSAC-5972) – Implementation and design gap review:** Compared the Jira acceptance criteria, [osac#1520](https://github.com/osac-project/osac/pull/1520), and the Netris CA design. Confirmed that core Jira acceptance criteria are met by the live validation. Identified several open gaps relative to the full design: production security enforcement (rejecting certificate validation bypass in production profiles) is not yet implemented; ConfigMap lifecycle and authorization controls are absent; protected launch-input enforcement is not wired across all launch paths; canonical inventory coverage is not guarded; and several test scenarios from the design matrix are missing. The PR is also still blocked from a green gate due to a missing review label and a pending CodeRabbit request for improved TLS test coverage. Next step is to decide which design-level controls are in scope for this ticket versus a follow-up before closing out the PR.

## Risks & Challenges
- VMaaS E2E has failures across multiple test areas; a retest was requested and a known-issue check is in progress, blocking the CI result for [osac#1520](https://github.com/osac-project/osac/pull/1520).
- [osac#1520](https://github.com/osac-project/osac/pull/1520) has an open CodeRabbit `CHANGES_REQUESTED` for TLS test improvements and a failing label gate, so the aggregate CI status is not yet green.
- Several design-level security controls (production profile enforcement, ConfigMap authorization, launch-input policy boundary, inventory guard) are not implemented in the current PR; a decision is needed on scope before the implementation can be considered fully aligned with the design.
