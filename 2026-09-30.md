# Daily Status - 2026-09-30

## Accomplishments

- Fixed a lifecycle event bug on [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) where early provisioning events were silently dropped because a mid-cycle status update bypassed event recording; responded to review feedback and pushed the fix to [osac#1299](https://github.com/osac-project/osac/pull/1299), which remains blocked awaiting review.
- Rebuilt and stabilized the single-node test environment end to end so the provisioning e2e test could run: recreated the hardware inventory and discovery setup, registered the worker host type, rolled a new operator image, and stood up the test harness on the blade.
- Resolved a sequence of environment blockers that were preventing any successful provisioning run — missing cloud DNS credentials in the automation platform, a DNS zone/domain mismatch between the automation defaults and the actual cluster domain, missing time-sync sources for the worker node, and a VM boot-order problem that left the node stuck mid-install.
- Achieved a first fully successful provisioning run (~22 minutes to Ready) after applying a local workaround for an unreliable network-operator readiness check in the virtualized environment; the deletion phase also exercised successfully.
- Diagnosed why an expected intermediate lifecycle event never appeared: the provisioning stage was being inferred from upstream cluster conditions that do not become true in a predictable order, so the intermediate state was genuinely never observed. Redesigned the approach to emit events directly off the order's own conditions, aligning the event vocabulary with the story's design.
- Ran a full validation pass on that redesign and found three significant defects — duplicate events per milestone, events emitted before the status write that produced them, and a stall-detection watchdog that silently switched off late in provisioning. Fixed all three, each with a test proven to fail before the fix, plus a guard preventing future stages from disabling the watchdog again.
- Cleaned up branch hygiene (rebase onto main, commit message and sign-off conventions) and opened draft PR [osac#1328](https://github.com/osac-project/osac/pull/1328), stacked on [osac#1299](https://github.com/osac-project/osac/pull/1299).
- Updated the reviewer persona guidance with two new review lenses derived from the bugs found this cycle.

## Risks & Challenges

- [osac#1299](https://github.com/osac-project/osac/pull/1299) is blocked with no review, which in turn blocks [osac#1328](https://github.com/osac-project/osac/pull/1328) from being rebased and marked ready.
- The event vocabulary change is a producer/consumer contract split across two branches — the QE test helper was updated here, but its only real caller lives on a separate branch still written against the old names. Neither CI can detect the mismatch, so it would surface only in a live end-to-end run after merge. The two branches need to be reconciled before either lands.
- No acceptance criteria or test plan exist for this work, so validation can only assert internal soundness, not story completeness.
- Integration tests requiring a live cluster have not been run; nothing yet exercises these events through a full reconcile against a real hosted cluster.
- The workaround for the flaky network-operator readiness check exists only as uncommitted local edits on the test machine — it is undocumented, unversioned, and will be lost on the next environment wipe.
- A naming inconsistency between configuration fields and the new stage names was deliberately deferred, since renaming would break existing environment variable contracts.
- The e2e test still needs to be re-run against the new event vocabulary to confirm the fix.

## Key Effort

Driving [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) to a working state by getting the single-node test environment provisioning successfully end to end, then diagnosing and redesigning how cluster provisioning lifecycle events are emitted so they are accurate, non-duplicated, and durable.
