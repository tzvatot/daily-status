# Daily Status - 2026-09-30

## Accomplishments

- Fixed a lifecycle event bug on [osac#1299](https://github.com/osac-project/osac/pull/1299) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) where early provisioning events were silently dropped, and responded to reviewer feedback; PR remains blocked awaiting review.
- Rebuilt and stabilized the single-node test environment end to end, resolving a series of environment blockers: a stuck hardware inventory resource, host boot-order problems, missing cloud DNS credentials in the automation platform, mismatched DNS domain configuration, and missing time-synchronization sources on the worker VM.
- Achieved a successful end-to-end cluster provisioning run (~22 minutes) in the test environment after applying a local workaround for an unreliable network operator readiness check that was causing automation jobs to time out in the virtualized environment.
- Built a small operational tool for inspecting cluster order state and lifecycle history, which made diagnosing repeated test failures substantially faster.
- Diagnosed why an expected intermediate lifecycle event never appeared: the provisioning stage was being inferred from live cluster conditions that do not become ready in a predictable order, so an intermediate stage was genuinely never observed rather than lost.
- Reworked provisioning lifecycle events to be driven directly by persisted cluster order conditions instead of inferred stages, aligning the implementation with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) design, and opened draft PR [osac#1328](https://github.com/osac-project/osac/pull/1328) stacked on [osac#1299](https://github.com/osac-project/osac/pull/1299).
- Ran a full validation pass on that branch and caught three significant defects before publication: every milestone emitting duplicate events, events being emitted before the status write that should back them, and the stall watchdog silently switching off during the worker-joining window. All three were fixed with regression tests verified to fail against the offending change, plus a guard preventing any future stage from disabling the watchdog.
- Updated the end-to-end test expectations to the new event vocabulary and cleaned up branch history (rebase, sign-offs, ticket prefixes) ahead of review.

## Risks & Challenges

- [osac#1299](https://github.com/osac-project/osac/pull/1299) is blocked with no review; [osac#1328](https://github.com/osac-project/osac/pull/1328) cannot come out of draft until it merges.
- The producer of the new lifecycle events and its only consumer live on separate branches written against different event vocabularies, and neither CI pipeline can detect the mismatch — it would only surface post-merge during a live end-to-end run. The two branches need to be reconciled before either merges.
- No acceptance criteria or test plan exist for this work, so validation can only claim internal soundness, not story completeness.
- Integration tests requiring a live cluster have not been run; nothing yet exercises these events through a full reconcile against real infrastructure.
- The automation-platform workaround that unblocked provisioning is local to the test machine and uncommitted, so it will be lost on the next environment rebuild.
- A naming inconsistency between stall-threshold configuration and the new stage names was deferred, since renaming would break existing environment variable overrides.
- The revised end-to-end test has not yet been re-run against the new event vocabulary.

## Key Effort

Getting the single-node test environment provisioning reliably end to end, and using what that exposed to correct and harden the cluster provisioning lifecycle event model.
