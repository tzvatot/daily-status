# Daily Status - 2026-09-30

## Accomplishments

- Addressed review feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) by fixing a bug where early lifecycle events were silently dropped when a mid-provisioning status update bypassed event recording; pushed the fix and replied to the reviewer. PR remains blocked awaiting review.
- Restored the single-node test environment on the CI blade end-to-end: rebuilt a working hardware inventory and discovery setup, registered the worker host type, deployed the updated operator image, and stood up the Python e2e test harness.
- Diagnosed and resolved a chain of environment blockers preventing provisioning from succeeding: missing cloud DNS credentials in the automation platform, a base-domain mismatch between the platform defaults and the actual CI domain, missing time-sync sources for the worker node, boot-order issues preventing the node from transitioning between discovery and installed states, and residual cluster objects left behind by earlier teardowns.
- Achieved a first successful provisioning run (~22 minutes to Ready) after applying a local workaround that removes two long cluster-operator wait steps from the automation flow, which were timing out on an unreliable network-operator readiness probe in the nested-virtualization environment.
- Investigated the resulting e2e test failure over a missing intermediate lifecycle event and confirmed the root cause: provisioning stages were being inferred from live hosted-cluster conditions that do not become true in a predictable order, so an intermediate stage was genuinely never observed rather than lost.
- Reworked the lifecycle event model to align with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) design — each provisioning condition now is a stage, with events emitted once on first transition and the persisted condition serving as the deduplication key. Opened draft PR [osac#1328](https://github.com/osac-project/osac/pull/1328), stacked on [osac#1299](https://github.com/osac-project/osac/pull/1299).
- Ran a formal validation pass on the new branch and found three high-severity defects before publishing: duplicate events emitted per milestone, events emitted before the status write that could survive its failure, and a silently disabled stall watchdog for the final provisioning stage. All three were fixed with regression specs that were each verified to fail against the commit they fix, plus a drift guard so a future stage cannot disable the watchdog unnoticed.
- Updated the e2e test assertions to the new event vocabulary, rebased the branch onto main, and cleaned up commit metadata before force-pushing.
- Built a status-inspection utility for cluster orders (phase, automation job, and per-order lifecycle events) to speed up debugging on the blade, and extended the senior reviewer persona with two new review lenses drawn from this week's findings.

## Risks & Challenges

- [osac#1299](https://github.com/osac-project/osac/pull/1299) is blocked with no review; [osac#1328](https://github.com/osac-project/osac/pull/1328) cannot be marked ready until it merges and the stacked commits are dropped.
- The automation-platform workaround that skips cluster-operator readiness waits exists only as uncommitted local edits on the blade. It is undocumented in version control and will be lost on the next environment wipe.
- No acceptance criteria or test plan exist for this work, so validation can only assert internal soundness, not story completeness.
- The lifecycle-event contract with QE is unverified: the producer and consumer live on separate branches with mismatched vocabularies, and neither CI pipeline can detect the mismatch — it would only surface post-merge in a live run.
- Integration tests requiring a live cluster have not been run; nothing yet exercises these events through a full reconcile against a real hosted cluster.
- The e2e test still needs to be re-run against the new event vocabulary.
- Underlying environmental fragility remains: the network operator readiness probe is unreliable under nested virtualization, and several environment settings that were lost in a prior teardown were never documented.

## Key Effort

Stabilizing the single-node e2e test environment and reworking the cluster provisioning lifecycle event model so that each stage is reported exactly once and reliably.
