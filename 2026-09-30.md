# Daily Status - 2026-09-30

## Accomplishments
- Addressed reviewer feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) by identifying and fixing a defect where early lifecycle status transitions were silently dropped during provisioning callbacks, ensuring status events are reliably recorded; tests and linting pass, changes pushed and response posted to the reviewer.
- Updated internal reviewer guidance to capture two new review lenses learned from this bug — auditing call sites when return signatures change, and checking for divergent write paths to the same state.
- Brought the single-node test environment back to a working state after a full wipe: verified the platform install, rebuilt the hardware discovery configuration so the worker host could register, refreshed the operator image, and registered the required host type.
- Stood up the end-to-end test harness on the test blade and drove four successive test runs, diagnosing and resolving a series of environment issues along the way — orphaned orders from misconfigured environment variables, an agent lost due to incorrect boot ordering, missing AWS credentials in the automation platform (now persisted and documented in the runbook), and a DNS zone default that pointed at the wrong domain. DNS record creation in Route53 is now confirmed working.
- Built a status utility that summarizes all cluster orders with their phase and associated automation job state, deployed both locally and on the blade, to speed up future triage.

## Risks & Challenges
- **Blocked on domain mismatch:** the hosted cluster domain is auto-derived with an extra prefix while the external access domain is not part of the chart at all and falls back to an unrelated default. The agent resolves one domain while DNS records are created at another, and there is no external DNS controller to reconcile them. Root cause is that the prior environment relied on manual overrides that were destroyed during the wipe and are not captured in the CI profile.
- **Blocked on time synchronization:** the worker VM cannot reach any NTP server because the discovery environment has no NTP sources configured and the setup tooling does not set them. This was also previously configured by hand and never documented.
- Both blockers are preventing the current end-to-end run from progressing past agent validation, even though the control plane comes up healthy. Planned fixes are identified (align the two domains via configuration, add an NTP source to the discovery environment, clean up the stuck order, and rerun).
- Broader concern: several environment prerequisites existed only as undocumented manual changes, so each teardown costs significant rediscovery time. Runbook updates are underway to close this gap.

## Key Effort
Restoring and validating the single-node end-to-end test environment after a full teardown, while landing review feedback on the status-event handling fix.
