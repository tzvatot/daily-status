# Daily Status - 2026-09-30

## Accomplishments

- Fixed an event-emission defect surfaced in review on [osac#1299](https://github.com/osac-project/osac/pull/1299) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)), where a mid-provisioning status update silently suppressed early lifecycle events; responded to the reviewer and pushed the fix, PR still awaiting review.
- Rebuilt the single-node test environment end to end to get an e2e provisioning run working: restored a usable hardware discovery path, registered the worker host type, deployed a fresh operator image, and stood up the test harness on the lab machine.
- Worked through a sequence of environment blockers that prevented provisioning from succeeding — missing cloud DNS credentials in the automation platform, a base-domain mismatch between the cluster chart defaults and the actual CI domain, missing time-sync sources for the worker, incorrect boot ordering at multiple lifecycle points, and leftover resources from prior failed runs.
- Achieved a successful end-to-end provisioning run (~22 minutes to Ready) after applying a local workaround that skips an unreliable network-operator readiness wait in the automation platform; the workaround is intentionally not committed and remains a known gap.
- Diagnosed why the e2e test still failed on a missing intermediate lifecycle event: the provisioning stage was being inferred from hosted-cluster conditions that do not become true in the assumed order, so an intermediate stage was genuinely never observable. Reworked the design to emit events directly off the order's own conditions, aligning the implementation with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) design.
- Ran a full validation pass on the reworked branch and found three high-severity defects: every provisioning milestone emitted duplicate events, milestone events were emitted before the status write that should back them, and the stall watchdog silently switched off for the final provisioning stage — meaning a cluster whose workers never joined would hang without any signal. Fixed all three, added regression specs each verified to fail against the commit it fixes, plus a guard preventing a future stage from disabling the watchdog again.
- Updated the e2e test helper to the new event vocabulary, cleaned up branch history, rebased onto main, and opened [osac#1328](https://github.com/osac-project/osac/pull/1328) as a draft stacked on [osac#1299](https://github.com/osac-project/osac/pull/1299).
- Extended the reviewer persona with two new review lenses derived from the class of bug found in [osac#1299](https://github.com/osac-project/osac/pull/1299), and built a status tool that surfaces cluster order phase, automation job outcome, and lifecycle events in one view.

## Risks & Challenges

- [osac#1299](https://github.com/osac-project/osac/pull/1299) is blocked with no review; [osac#1328](https://github.com/osac-project/osac/pull/1328) cannot move out of draft until it merges.
- The producer of the lifecycle events and the QE test that consumes them live on separate branches written against different event vocabularies. Neither CI can detect the mismatch, so it would only surface post-merge in a live e2e run — the two branches need to be reconciled before either lands.
- No acceptance criteria or test plan exist for this work, so validation can only assert internal soundness, not story completeness. Integration tests requiring a live cluster have not been run.
- The automation-platform workaround that skips the unreliable network-operator wait is local-only on the lab machine and uncommitted; the underlying operator instability in nested-virtualization environments is unresolved.
- The e2e test still needs a re-run against the new event vocabulary.
- A naming inconsistency between the stall-threshold configuration and the new stage names was deliberately deferred, since renaming would break existing environment-variable configuration.

## Key Effort

Getting the cluster-order lifecycle event work ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) to a correct and verifiable state — rebuilding the single-node test environment to prove it end to end, and redesigning stage-event emission around persisted conditions after validation exposed duplicate events, unbacked emissions, and a disabled stall watchdog.
