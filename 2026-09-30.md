# Daily Status - 2026-09-30

## Accomplishments

- Addressed review feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441), fixing a defect where early cluster lifecycle events were silently dropped because a mid-provisioning status update bypassed event recording; tests and linting pass and the fix is pushed for the reviewer.
- Extended the internal senior reviewer persona guidance with two new review lenses to catch this class of issue earlier in future reviews.
- Rebuilt and stabilized the single-node test environment end to end so the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) e2e test could run: restored a usable discovery/inventory setup, corrected boot ordering for the worker VM, registered the required host type, and deployed an updated operator image.
- Resolved a sequence of environment blockers that were preventing provisioning from succeeding: missing cloud DNS credentials in the automation platform, DNS zone and base-domain mismatches between the deployment chart and automation defaults, and time-sync failures on the worker node. Each fix was verified against live provisioning runs.
- Documented the cloud credential setup in both runbook versions and built a small operational script (available locally and on the test host) that surfaces every cluster order with its phase and associated automation job status, cutting debugging time significantly.
- Achieved a successful full provisioning run (~22 minutes) through the complete lifecycle to Ready, followed by deprovisioning, after applying a local-only workaround for an unreliable network operator readiness probe in the nested-virtualization environment. Note: this workaround is uncommitted and environment-specific.
- Investigated the remaining e2e test failure over a missing intermediate lifecycle event and confirmed the root cause: the provisioning stage was inferred from hosted cluster conditions that do not become true in the assumed order, so an intermediate stage was genuinely never observable rather than being lost to a race.
- Reworked the lifecycle event model to align with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) design — each cluster order condition now represents a provisioning stage and emits an event on first transition, with conditions providing deduplication. Full unit test suite passes and the branch is pushed to a fork; PR not yet opened.

## Risks & Challenges

- The successful provisioning run depended on an uncommitted local workaround that skips waiting for cluster operator readiness. This is not a real fix and means the test environment currently declares success earlier than production behavior would; the underlying network operator instability in nested virtualization remains unaddressed.
- The lifecycle event rework is not yet submitted for review. Remaining work: open the PR, update e2e test assertions to the new condition-based event names, and re-run the e2e test to confirm.
- Substantial time was spent on environment reconstruction rather than product work, driven by prior manual configuration that was lost in a teardown and never captured in the CI profile. Without folding these settings into the provisioning profile, the same class of failures will recur on the next rebuild.

## Key Effort

Stabilizing the single-node e2e test environment for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) and redesigning cluster order lifecycle event emission to be condition-based rather than inferred from out-of-order hosted cluster state.
