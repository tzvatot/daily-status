# Daily Status - 2026-09-30

## Accomplishments
- Addressed reviewer feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) by fixing a defect where early lifecycle events were silently dropped when status was updated mid-provisioning; tests and linting pass and the reviewer has been responded to.
- Enhanced the internal senior reviewer persona with two additional review lenses to catch similar classes of issues earlier.
- Brought the single-node test environment back to a working state after a full wipe, including rebuilding hardware inventory, re-registering the worker host, correcting VM boot ordering, and rolling a new operator image.
- Stood up an end-to-end test harness on the test machine and drove it through several iterations, diagnosing and resolving a series of environment blockers: missing cloud DNS credentials in the automation platform, mismatched DNS base domains between the deployment chart and automation defaults, and missing time-sync configuration for the worker node.
- Identified that the cluster-operator readiness wait in the automation workflow is unreliable in nested-virtualization environments and applied a local-only workaround so provisioning can complete; this is not committed and remains an open item for a proper fix.
- Achieved a successful end-to-end provisioning run (~22 minutes) reaching a Ready cluster, followed by the deprovision flow.
- Investigated the resulting test failure over a missing intermediate lifecycle event and confirmed the root cause: provisioning stage was being inferred from live hosted-cluster conditions that do not become true in the assumed sequential order, so an intermediate stage was genuinely never observable.
- Reworked the provisioning event model to align with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) design — emitting events directly off condition transitions rather than a derived stage vocabulary — with the full test suite passing and the branch pushed; PR not yet opened.
- Built a small operational tooling script to give at-a-glance visibility into cluster order state and associated automation job status.
- Cleaned up multiple orphaned cluster orders, namespaces, and stale resources left behind by failed runs, and documented the credential setup steps in the runbook.

## Risks & Challenges
- The automation workflow change that skips cluster-operator readiness waits exists only as a local modification on the test machine and is not in source control; it needs a durable upstream fix or it will be lost and block future runs.
- The underlying network-operator instability in the nested-virtualization test environment remains unaddressed and could cause intermittent provisioning timeouts.
- The lifecycle event rework still needs a PR, matching updates to the end-to-end test assertions, and a full re-run before it can be considered validated.
- Several environment prerequisites (time-sync sources, DNS domain overrides, credentials) were undocumented and only discovered through failures, suggesting the environment setup tooling is incomplete.

## Key Effort
Restoring and validating the single-node end-to-end provisioning environment for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441), and reworking cluster provisioning lifecycle events to be driven by condition transitions rather than inferred stages.
