# Daily Status - 2026-09-30

## Accomplishments
- Addressed reviewer feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441): diagnosed and fixed a defect where early lifecycle transition events were silently dropped because a mid-cycle status update bypassed event recording; tests and linting pass, changes pushed and response posted to the reviewer. PR still pending merge.
- Strengthened the internal Kubernetes reviewer persona with two additional review lenses (auditing call sites when return signatures change, and identifying divergent write paths) to catch this class of bug earlier.
- Rebuilt and validated the single-node test environment after an earlier teardown: confirmed the platform install succeeded, restored a working hardware inventory and discovery path for the worker, registered the required host type, and rolled a new operator image carrying the fix.
- Stood up the end-to-end test harness on the test machine and drove four successive test runs, resolving a new blocker each time — test invocation issues, worker boot-order regressions that disconnected the agent, missing cloud DNS credentials in the automation platform, and an incorrect default DNS zone. External DNS record creation is now confirmed working.
- Documented the cloud credential setup in the environment runbook and built a status script that surfaces all cluster orders alongside their automation job IDs and outcomes, to speed up future debugging.

## Risks & Challenges
- End-to-end test remains blocked. Two environment gaps are preventing cluster provisioning from completing:
  - **DNS domain mismatch** — the hosted cluster's base domain is auto-derived with an extra prefix while external DNS records are created without it, so the agent cannot resolve the API endpoint. The external access domain isn't represented in the deployment chart at all and falls back to an unrelated default. There is no DNS controller reconciling the difference.
  - **Time synchronization failure** — the worker VM cannot reach any time server because the discovery configuration doesn't declare one, even though a server is available on the host.
- Root cause for both: the previous environment relied on undocumented manual overrides that were lost during the wipe, and the CI profile used to rebuild does not carry these values. Fixes are identified (override both domain settings consistently, add a time source to the discovery configuration, clean up the stuck order and re-run) but not yet applied.
- Several orphaned cluster orders and namespaces were left behind by failed runs and required manual cleanup; more cleanup is pending.

## Key Effort
Restoring and debugging the single-node end-to-end test environment to validate the cluster provisioning event-recording fix for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441).
