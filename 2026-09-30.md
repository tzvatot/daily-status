## Risks & Challenges
- **Blocked on DNS domain mismatch:** the Helm chart derives the hosted cluster domain with an extra prefix while the external access domain is not modeled in the chart at all, so agents resolve a different hostname than the one the DNS records are created under. There is no DNS synchronization controller in the environment, so both values must be aligned manually. Root cause is that the previous environment relied on undocumented manual overrides that were lost during the wipe, and the CI profile does not supply these values.
- **Blocked on time synchronization failure:** the worker VM cannot reach any time server because the discovery environment has no time sources configured and the provisioning script does not set them. This was also previously configured by hand and never documented.
- The in-flight end-to-end test remains stuck at agent validation pending both fixes; the control plane comes up but the worker cannot be validated.
- Broader concern: multiple environment settings were only ever applied manually, making the test environment non-reproducible after teardown.
