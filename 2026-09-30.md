# Daily Status - 2026-09-30

## Accomplishments

- Addressed review feedback on [osac#1299](https://github.com/osac-project/osac/pull/1299) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) by fixing a defect where early lifecycle events were silently dropped when provisioning status updates bypassed event recording; tests and linting pass and the reply is posted, but the PR remains blocked awaiting review.
- Rebuilt and stabilized the single-node test environment end-to-end so the lifecycle-event e2e test could run: recovered a stuck discovery environment, corrected host registration and boot ordering, supplied missing time-sync and DNS domain configuration, and provisioned the missing cloud DNS credentials in the automation platform. Documented the credential setup in the runbook and added a status tool that summarizes cluster orders alongside their automation job state and lifecycle events.
- Achieved a successful provisioning run (~22 minutes) after applying a local-only workaround for an unreliable network operator readiness check that was timing out in the nested-virtualization environment.
- Investigated the resulting test failure over a missing intermediate lifecycle event and confirmed the root cause: the code inferred provisioning stages from live control-plane conditions that do not become true in a predictable order, so an intermediate stage was genuinely never observed. Reworked the design to align with the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) intent — each provisioning condition is itself a stage, with events emitted on first transition and the persisted condition serving as deduplication.
- Ran a full validation pass on that rework and found three high-severity issues, each reproduced empirically rather than by inspection: duplicate events for every provisioning milestone, events emitted before the status write that would survive its failure, and stall detection silently switching off for the final provisioning stage — which would have let a cluster with workers that never join hang indefinitely without any warning signal. Fixed all three plus two lower-severity items, added seven specs each verified to fail against the commit it fixes, including a guard preventing a future stage from disabling the stall watchdog.
- Cleaned up branch history, rebased onto the current main, and opened draft PR [osac#1328](https://github.com/osac-project/osac/pull/1328) stacked on [osac#1299](https://github.com/osac-project/osac/pull/1299).

## Risks & Challenges

- [osac#1299](https://github.com/osac-project/osac/pull/1299) is blocked with no review; [osac#1328](https://github.com/osac-project/osac/pull/1328) cannot be marked ready until it merges, and it currently carries the parent's commits.
- The event vocabulary change spans two branches — the producer in one, the QE consumer in another — and neither CI pipeline can detect a mismatch between them, so a contract break would only surface post-merge in a live end-to-end run. The two branches need to be diffed before either merges.
- No acceptance criteria or test plan exist for this work, so validation can only confirm the branch is internally sound, not that the story is satisfied. Integration tests requiring a live cluster have not been run.
- The workaround for the unreliable network operator readiness check exists only as uncommitted local edits on the test blade and needs a proper resolution.
- Environment fragility remains a recurring cost: repeated teardowns destroyed undocumented manual configuration, and orphaned resources from failed runs required manual cleanup on several occasions.

## Key Effort

Driving the cluster-order lifecycle event work for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) to a correct and verifiable state, spanning both the controller redesign and the reconstruction of the single-node test environment needed to validate it.
