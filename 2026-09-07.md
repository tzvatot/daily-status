# Daily Status - 2026-09-07

## Accomplishments

- Investigated why a one-worker HyperShift cluster was stuck progressing despite a healthy hosted control plane. Root-caused the issue to the infrastructure availability policy being set to `HighlyAvailable` instead of `SingleReplica`, causing guest-cluster operators to fail scheduling on a single worker node. Traced the policy precedence through the standalone deployment overlay and AAP configuration layering. Applied an immediate workaround and verified that newly created clusters pick up the corrected policy. A fix for the standalone recipe's default configuration is still needed. Monitoring of the replacement cluster through final availability is ongoing. ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441))

- Deployed the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 semantic sub-stage PR ([osac#767](https://github.com/osac-project/osac/pull/767)) to the validation environment and began a clean end-to-end retest. Confirmed a prior test cluster reached full availability before teardown. Created a fresh cluster and observed the first merged semantic feedback reporting the expected sub-stage. Monitoring through remaining transitions and final ready state is ongoing.

- Identified a deletion bug where a cluster order remains stuck in `Deleting` due to a retained storage finalizer after all other cleanup (HyperShift teardown, AAP deprovision job, feedback cleanup) has succeeded. Shared the issue and reproduction steps with the storage working group. The likely cause is that the cluster order deletion does not reliably trigger the owner tenant's storage reconciliation. Awaiting storage-controller investigation.

- Corrected four reversed Jira dependency links so that [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) correctly blocks [OSAC-4443](https://redhat.atlassian.net/browse/OSAC-4443), [OSAC-4444](https://redhat.atlassian.net/browse/OSAC-4444), [OSAC-4445](https://redhat.atlassian.net/browse/OSAC-4445), and [OSAC-4446](https://redhat.atlassian.net/browse/OSAC-4446).

- Reviewed the updated stall-detection PR ([osac#783](https://github.com/osac-project/osac/pull/783)). Confirmed the fix correctly preserves the stalled status across reconcile cycles and that all tests and linting pass. Requested Riccardo's review; awaiting his feedback.

- Implemented transition events for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.04: the cluster order controller now emits Kubernetes events when provisioning sub-stages change or when deletion begins, with duplicate suppression. Added unit tests covering all transition paths at full coverage. Opened draft [osac#785](https://github.com/osac-project/osac/pull/785), stacked on the stall-detection PR. Awaiting review and CI.

## Risks & Challenges
