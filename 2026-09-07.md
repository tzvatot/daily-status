# Daily Status - 2026-09-07

## Accomplishments

- **Investigated one-worker HyperShift cluster availability failure:** Diagnosed why a single-worker CI cluster could not reach the available state. Guest-cluster infrastructure operators (ingress, image-registry, monitoring) were unable to schedule because the HostedCluster was created with a HighlyAvailable infrastructure policy, requiring replicas that a single worker cannot satisfy. Traced the policy-propagation path and confirmed the standalone deployment overlay explicitly injects HighlyAvailable, overriding the CI template's SingleReplica fallback. Applied a targeted configuration override to set the infrastructure policy to SingleReplica, recreated the test cluster, and verified the corrected policy reached the new HostedCluster.
- **Deployed and began validating merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 ([osac#767](https://github.com/osac-project/osac/pull/767)):** Built the merged image, rolled it out to the validation environment, and created a new test cluster to observe the semantic lifecycle substage transitions introduced by the PR. Initial feedback correctly reports the first substage. Observation of remaining transitions through terminal state is ongoing.
- **Reported and documented a cluster-storage finalizer deletion bug:** After deleting a test cluster, the backing order remains stuck in Deleting because the storage finalizer is never removed, even though all other cleanup (HyperShift teardown, deprovisioning job, feedback cleanup) completed successfully. Shared the issue and reproduction steps with the storage working group. Root cause appears to be that the deletion event does not reliably trigger the storage reconciliation path.

## Risks & Challenges

- The standalone deployment recipe defaults to HighlyAvailable infrastructure policy for HyperShift, which is incompatible with one-worker CI topologies. A configuration fix is still needed to align standalone with upstream CI values or expose an explicit per-deployment setting.
- The cluster-storage finalizer bug leaves deleted cluster orders in a Deleting state indefinitely, requiring storage-controller investigation by the storage team.

## Key Effort

Investigated and resolved a one-worker HyperShift availability failure caused by an infrastructure policy mismatch, and began end-to-end validation of the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) lifecycle substage reporting.
