# Daily Status - 2026-09-07

## Accomplishments
- Investigated why a one-worker HyperShift cluster could not reach available state. Root cause: the standalone deployment configuration injects a highly-available infrastructure policy, which requires multiple replicas that cannot schedule on a single worker node. Applied a configuration override to use single-replica infrastructure policy and verified a replacement cluster was created with the correct setting. Monitoring of the replacement cluster through full availability is still in progress. ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441))
- Merged [osac#767](https://github.com/osac-project/osac/pull/767) (Story 1.02 — semantic lifecycle sub-stages for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)). Deployed the merged image to the validation environment, confirmed a prior test cluster reached full availability, and created a new test cluster to validate post-merge sub-stage transitions. Observation of transitions through the terminal available state is still in progress.
- Reported a cluster deletion issue to the storage working group: after a hosted cluster is fully torn down and the deprovisioning job succeeds, the cluster order remains stuck in a deleting state due to a retained storage finalizer. Investigation points to a gap in how deletion events are propagated to the storage reconciler.
- Corrected reversed Jira dependency links so that [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) correctly blocks [OSAC-4443](https://redhat.atlassian.net/browse/OSAC-4443), [OSAC-4444](https://redhat.atlassian.net/browse/OSAC-4444), [OSAC-4445](https://redhat.atlassian.net/browse/OSAC-4445), and [OSAC-4446](https://redhat.atlassian.net/browse/OSAC-4446).

## Risks & Challenges
- The standalone deployment recipe defaults to highly-available infrastructure policy for HyperShift, which is incompatible with single-worker CI topologies. A configuration fix is still needed to align with upstream CI values or expose an explicit per-deployment setting.
- A cluster-storage finalizer is not being removed after cluster deletion, leaving cluster orders stuck in a deleting state. This requires storage-controller investigation by the storage working group.
- Post-merge validation of semantic lifecycle sub-stages is still in progress; the new test cluster has not yet reached the terminal available state.

## Key Effort
Investigated and resolved a one-worker HyperShift cluster availability issue caused by mismatched infrastructure availability policy, and began post-merge validation of semantic lifecycle sub-stages for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441).
