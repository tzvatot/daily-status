# Daily Status - 2026-09-07

## Accomplishments
- Merged [osac#767](https://github.com/osac-project/osac/pull/767) after approval.
- Investigated why a one-worker HyperShift test cluster remains stuck in a progressing state despite the hosted control plane being fully healthy. Confirmed that OSAC correctly waits for the cluster version to succeed before reporting availability.
- Diagnosed the root cause: the infrastructure availability policy defaults to highly-available, causing guest-cluster operators (image-registry, ingress, monitoring) to require multiple replicas and anti-affinity that a single worker cannot satisfy. The CI template intends a single-replica fallback for infrastructure policy, but this value is not reaching the live deployment — only the controller availability policy is correctly set.
- Identified next steps: investigate the policy-propagation gap (template vs. deployment mismatch, variable precedence, or handoff issue), apply a configuration workaround, recreate the test cluster with the correct policy, and verify end-to-end availability.
