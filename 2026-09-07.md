# Daily Status - 2026-09-07

## Accomplishments
- Merged [osac#767](https://github.com/osac-project/osac/pull/767) (Story 1.02 semantic lifecycle substages) after approval by Riccardo.
- Investigated why a one-worker HyperShift cluster could not reach full availability. Diagnosed that the hosted cluster was created with a HighlyAvailable infrastructure policy instead of SingleReplica, causing data-plane services (ingress, image registry, monitoring) to fail scheduling on a single worker node.
- Traced the policy-propagation path and confirmed the root cause: the standalone deployment recipe unconditionally injects HighlyAvailable for HyperShift mode, overriding the CI template's SingleReplica fallback. Applied a targeted configuration override and verified that newly created hosted clusters now receive the correct SingleReplica infrastructure policy.
- Deployed the merged [osac#767](https://github.com/osac-project/osac/pull/767) operator image to the validation environment and began retesting semantic substage transitions on a fresh cluster. Confirmed the first post-merge lifecycle feedback reports the expected substage progression.
- Identified and reported a cluster-storage finalizer retention bug: after a hosted cluster is fully deleted and its deprovision job succeeds, the cluster order remains stuck in Deleting because the storage finalizer is never removed. Shared the issue and reproduction steps with the storage working group.
- Corrected reversed Jira dependency links: [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) now correctly shows as blocking [OSAC-4443](https://redhat.atlassian.net/browse/OSAC-4443), [OSAC-4444](https://redhat.atlassian.net/browse/OSAC-4444), [OSAC-4445](https://redhat.atlassian.net/browse/OSAC-4445), and [OSAC-4446](https://redhat.atlassian.net/browse/OSAC-4446).
- Reviewed [osac#783](https://github.com/osac-project/osac/pull/783) (stalled provisioning detection), confirmed the stall-status reset fix is correct, and requested Riccardo's review.

## Risks & Challenges
- The standalone deployment recipe defaults infrastructure availability to HighlyAvailable for HyperShift, which breaks single-worker CI topologies. A configuration fix is still needed to align the standalone recipe with upstream CI values.
- A cluster-storage finalizer bug is blocking full cleanup of deleted cluster orders. The storage reconciler does not appear to be triggered reliably when an order is deleted, leaving orders stuck in Deleting state. This needs investigation by the storage team.
- Post-merge validation of [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 is still in progress — awaiting the new test cluster to reach terminal availability and confirm all semantic substage transitions end-to-end.

## Key Effort
Investigated and resolved a one-worker HyperShift cluster availability failure caused by an infrastructure availability policy misconfiguration, then began post-merge validation of the [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) semantic lifecycle substages feature.
