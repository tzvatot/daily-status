# Daily Status - 2026-09-07

## Accomplishments

- Merged [osac#767](https://github.com/osac-project/osac/pull/767) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 lifecycle feedback), approved by reviewer.
- Investigated why a one-worker HyperShift cluster remained stuck in a progressing state despite a healthy hosted control plane. Root-caused it to the infrastructure availability policy being set to HighlyAvailable, which forced guest-cluster operators (image-registry, ingress, monitoring) to require multiple replicas that cannot schedule on a single worker node. Traced the policy precedence through the standalone deployment configuration and confirmed it overrides the CI template's single-replica fallback. Applied a workaround by explicitly setting the infrastructure policy to SingleReplica and verified that newly created clusters pick up the correct setting.
- A permanent fix is still needed in the standalone deployment recipe so it defaults to SingleReplica for single-worker CI topologies instead of requiring a manual override.
- Deployed the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 operator image to the validation environment and confirmed the previous test cluster completed successfully (cluster ready, hosted control plane available, guest cluster version installed, worker joined). Created a new test cluster to validate the merged code's lifecycle feedback transitions; initial feedback is reporting the expected semantic sub-stage. Monitoring continues through terminal state.
- Reported a deletion bug to the storage working group: after a CaaS cluster is deleted and all HyperShift and automation cleanup completes, the cluster order remains stuck in Deleting due to a retained storage finalizer. The storage controller's teardown logic is not being triggered, likely because the owner tenant reconciliation is not reliably enqueued upon order deletion. Awaiting storage-controller investigation.

## Risks & Challenges

- The standalone deployment recipe defaults to a HighlyAvailable infrastructure policy for HyperShift, which prevents single-worker CI clusters from completing. A manual override is in place but the recipe needs a permanent fix.
- A storage finalizer bug causes deleted cluster orders to remain in a Deleting state indefinitely. This does not block worker reuse but leaves stale resources until the storage team investigates.

## Key Effort

Investigated and resolved a one-worker HyperShift availability issue caused by an infrastructure policy misconfiguration, and began validating the merged lifecycle feedback improvements in the CI environment.
