# Daily Status - 2026-09-07

## Accomplishments

- Merged [osac#767](https://github.com/osac-project/osac/pull/767) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 lifecycle feedback), approved by Riccardo.
- Investigated why a one-worker HyperShift cluster could not reach available state. Root cause: the infrastructure availability policy was set to highly-available instead of single-replica, causing data-plane services (ingress, image registry, monitoring) to require anti-affinity and host ports that a single worker cannot satisfy. Traced the policy propagation through the standalone deployment overlay configuration and confirmed it intentionally overrides the per-template fallback.
- Applied an immediate workaround by setting the infrastructure availability policy to single-replica in the deployment configuration, created a replacement test cluster, and verified the corrected policy propagated to the new cluster. The standalone recipe configuration gap (defaulting to highly-available for HyperShift) still needs a permanent fix.
- Deployed the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) image to the validation environment, confirmed the previous test cluster reached full readiness, then created a new test cluster to validate the post-merge semantic lifecycle substage transitions. Initial feedback is reporting correctly; monitoring through remaining substages is still in progress.
- Identified and reported a cluster-storage finalizer retention issue: after a hosted cluster is fully deleted and the deprovision job succeeds, the cluster order remains stuck in a deleting state because the storage finalizer is never removed. Shared the reproduction flow with the storage working group. The likely cause is that deletion events are not reliably triggering the storage reconciliation; investigation by the storage team is needed.
