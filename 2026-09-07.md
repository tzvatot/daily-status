# Daily Status - 2026-09-07

## Accomplishments

- **Investigated one-worker HyperShift cluster availability issue** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): Diagnosed why a single-worker hosted cluster was stuck progressing — infrastructure services required high-availability replicas that could not schedule on one node. Traced the root cause to the standalone deployment overlay injecting a high-availability infrastructure policy that overrides the intended single-replica fallback for CI topologies. Applied an immediate configuration workaround, created a replacement cluster, and confirmed the fix produces the correct single-replica policy on new clusters.
- **Merged [osac#767](https://github.com/osac-project/osac/pull/767)** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02): PR approved and merged.
- **Began post-merge deployment retest of Story 1.02** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)): Deployed the merged operator image to the validation environment, confirmed the previous test cluster reached a fully ready state, tore it down cleanly, and created a fresh cluster to validate the new semantic lifecycle sub-stage transitions end-to-end. Initial feedback shows the expected first sub-stage; continuing to observe remaining transitions.
- **Reported cluster-storage finalizer retention bug**: After deleting a hosted cluster, all cleanup steps (deprovisioning job, namespace removal, feedback finalizer) succeeded, but the storage finalizer remains, leaving the order stuck in a deleting state. Shared reproduction steps and evidence with the storage working group. Likely cause is a missing or lost reconciliation event during rapid teardown.

## Risks & Challenges

- The standalone deployment recipe defaults to high-availability infrastructure policy for HyperShift, which is incompatible with one-worker CI topologies. A configuration fix for the recipe template is still needed.
- The cluster-storage finalizer retention bug can leave deleted cluster orders in a dangling state; root-cause fix requires storage-controller investigation by the storage team.

## Key Effort

Investigated and worked around a HyperShift infrastructure-availability policy misconfiguration blocking single-worker cluster readiness, and began validating the merged lifecycle sub-stage reporting feature end-to-end.
