# Daily Status - 2026-09-07

## Accomplishments

- **Investigated one-worker HyperShift cluster availability failure.** Diagnosed why a single-worker hosted cluster could not reach the available state: the infrastructure availability policy was being set to HighlyAvailable instead of SingleReplica, causing data-plane services (ingress, image registry, monitoring) to require anti-affinity across multiple nodes that don't exist in a one-worker topology. Traced the root cause to the standalone deployment overlay, which unconditionally injects HighlyAvailable into the configuration, overriding the CI template's SingleReplica fallback. Applied an immediate workaround and verified that a replacement cluster was created with the correct SingleReplica policy. Monitoring of the replacement cluster through full availability is still in progress, and a permanent fix to the standalone recipe defaults is still needed.

- **Merged [osac#767](https://github.com/osac-project/osac/pull/767)** ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02). Deployed the merged operator image to the validation environment, confirmed the prior test cluster reached full readiness, then created a new cluster to validate the semantic substage lifecycle transitions introduced by the PR. Initial feedback shows the expected new substage reporting. Observation of the full transition sequence through the terminal state is still in progress.

- **Reported cluster-storage finalizer retention bug** to the storage working group. After deleting a hosted cluster, the backing order remains stuck in Deleting because the storage finalizer is never removed, even though all other cleanup (HyperShift teardown, deprovisioning job, feedback cleanup) completed successfully. The likely cause is that the cluster deletion does not reliably trigger the storage reconciliation needed to remove the finalizer. Awaiting investigation by the storage team.

## Risks & Challenges

- The standalone deployment recipe defaults infrastructure availability to HighlyAvailable for HyperShift mode, which prevents one-worker CI clusters from reaching the available state. A manual workaround is in place, but a permanent configuration fix is still needed.
- The cluster-storage finalizer retention bug leaves deleted cluster orders in a Deleting state indefinitely. This does not block worker reuse but leaves stale resources and could mask future deletion issues.

## Key Effort

Investigated and worked around a HyperShift availability-policy misconfiguration blocking single-worker CI clusters, while validating the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) semantic substage reporting in the deployment environment.
