# Daily Status - 2026-09-07

## Accomplishments

- Investigated why a one-worker HyperShift cluster could not reach full availability. Diagnosed that guest-cluster operators (image-registry, ingress, monitoring) failed to schedule because the infrastructure availability policy was set to highly-available mode, requiring replicas that a single worker cannot satisfy. Traced the root cause to the standalone deployment overlay unconditionally injecting a highly-available infrastructure policy, overriding the per-template single-replica fallback intended for small CI topologies. Applied a workaround by explicitly setting single-replica infrastructure policy in the deployment configuration and verified a replacement cluster was created with the correct policy. A fix for the standalone recipe default is still needed, and the replacement cluster is being monitored through full availability.

- Deployed the merged [osac#767](https://github.com/osac-project/osac/pull/767) ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02) image to the validation environment and confirmed the prior test cluster reached full readiness before teardown. Created a new test cluster to validate semantic sub-stage lifecycle transitions end-to-end on the merged code. Initial feedback shows the expected first sub-stage; monitoring is ongoing through the terminal state.

- Identified and reported a bug where a cluster-storage finalizer is not removed after CaaS cluster deletion, leaving the backing order stuck in a deleting state indefinitely. All other teardown steps (HyperShift cleanup, deprovisioning job, feedback cleanup) completed successfully. Shared the issue and reproduction steps with the storage working group. The likely root cause is that the owner tenant's storage reconciliation is not reliably triggered when the order is deleted. This requires storage-controller investigation.

## Risks & Challenges

- The standalone deployment recipe defaults to highly-available infrastructure policy for HyperShift, which is incompatible with single-worker CI topologies. A configuration fix is pending.
- The cluster-storage finalizer retention bug can leave deleted cluster orders in a perpetual deleting state, potentially blocking resource reuse in environments with limited capacity.

## Key Effort

Investigated and worked around a one-worker HyperShift availability failure caused by an infrastructure policy misconfiguration, then validated the merged [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) lifecycle sub-stage reporting on a clean deployment.
