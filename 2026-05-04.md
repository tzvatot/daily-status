# Daily Status - 2026-05-04

## Accomplishments
- **CaaS demo environment:** Re-published AAP templates after [osac-aap#274](https://github.com/osac-project/osac-aap/pull/274) merged, verified that cluster templates no longer expose sensitive parameters and that cluster creation works with explicit secret file flags
- **Fixed osac-operator crash loop on vmaas-dev:** Diagnosed missing RBAC permissions for the PublicIP resource and patched the cluster role; operator is now running with all controllers syncing
- **Fixed AuthConfig tenant assignment:** Corrected tenant assignment so only the template-publisher service account receives the shared tenant, resolving a cluster creation failure requiring exactly one tenant
- **Fixed missing Ansible role reference ([osac-aap#282](https://github.com/osac-project/osac-aap/pull/282)):** A recent Netris change ([MGMT-23420](https://issues.redhat.com/browse/MGMT-23420)) introduced a short-name role reference that couldn't be resolved; fixed by using the fully qualified collection name. PR merged and deployed to vmaas-dev
- **Cleaned up stale ESI routers:** Router quota was full with 5 orphaned routers from deleted or missing cluster orders; removed them to unblock new cluster provisioning

## Risks & Challenges
- **Blocked on bare-metal agent availability:** All suitable agents are bound to an existing cluster order, preventing new cluster provisioning. Need to free up agents or relabel unassigned ones before the CaaS demo can proceed
- **Possible router cleanup bug:** Four of the five orphaned routers had no matching cluster order in Kubernetes, suggesting that router resources may not be reliably cleaned up when cluster orders are deleted or deprovision jobs fail — needs investigation

## Key Effort
Unblocking the CaaS demo environment by resolving a chain of infrastructure issues (operator crash, tenant misconfiguration, missing role reference, and router quota exhaustion) on the vmaas-dev cluster.
