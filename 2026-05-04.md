# Daily Status - 2026-05-04

## Accomplishments

- **CaaS demo environment**: Re-published AAP templates after merging PR [osac-aap#274](https://github.com/osac-project/osac-aap/pull/274), confirmed template parameters were removed, and verified cluster creation works with the new explicit secret/key file flags.
- **Fixed osac-operator crash loop on vmaas-dev**: Diagnosed missing RBAC permissions for the PublicIP resource, patched the cluster role, updated the operator image, and confirmed all controllers are healthy.
- **Fixed AuthConfig tenant assignment**: Resolved a misconfiguration where all service accounts were incorrectly assigned to multiple tenants, causing cluster creation to fail. Corrected tenant scoping so only the template-publisher SA gets cross-tenant access.
- **Fixed manage_agents role resolution failure**: Root-caused an AAP job failure to a short role name introduced in a recent Netris commit ([MGMT-23420](https://issues.redhat.com/browse/MGMT-23420)). Switched to fully-qualified role names, deployed the fix, verified it resolved the failure, and merged [osac-aap#282](https://github.com/osac-project/osac-aap/pull/282).
- **Cleaned up stale ESI routers**: Removed 5 orphaned routers that were consuming the full router quota, blocking new cluster creation. Identified that the role resolution bug caused both create and delete paths to fail, leaving resources orphaned.
- **Recovered vmaas-dev environment**: Deleted all failed demo clusters, cleaned stale agent labels, removed finalizers from 6 stuck ClusterOrders (blocked by a Route 53 IAM permission gap), and restored the environment to a clean state with 2 free agents available.
- **Reviewed and approved PRs**: Re-reviewed [fulfillment-service#481](https://github.com/osac-project/fulfillment-service/pull/481) (installation guide) — all prior findings addressed, approved. Approved [osac-aap#268](https://github.com/osac-project/osac-aap/pull/268) (Netris CaaS fixes) after confirming the last open item via Slack. Reviewed [osac-aap#279](https://github.com/osac-project/osac-aap/pull/279) ([MGMT-24176](https://issues.redhat.com/browse/MGMT-24176), BMH agent import) and posted 3 important findings. Also reviewed own [osac-aap#282](https://github.com/osac-project/osac-aap/pull/282) and flagged a pre-existing duplicate task to the author.
- **Created `/slack-read` command**: Built a Claude Code command to read and summarize Slack threads directly from URLs.

## Risks & Challenges

- **Route 53 IAM permission gap**: The DNS cleanup step in the cluster delete flow fails because the IAM user is missing a required Route 53 permission. This is a separate blocker from the role resolution fix and will cause delete jobs to fail on DNS cleanup until resolved.
- **Orphaned ESI resources on deletion**: Force-deleting ClusterOrders by removing finalizers skips the AAP cleanup flow, leaving routers and other ESI resources orphaned. At least one stale router remains from a force-deleted order.

## Key Effort

Restored the vmaas-dev CaaS demo environment to a working state by diagnosing and fixing a chain of failures (operator crash, tenant misconfiguration, role resolution bug, router quota exhaustion) and cleaning up orphaned resources.
