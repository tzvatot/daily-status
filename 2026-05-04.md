# Daily Status - 2026-05-04

## Accomplishments

- **CaaS demo environment updated**: Re-published AAP templates after merging [osac-aap#274](https://github.com/osac-project/osac-aap/pull/274), removing hardcoded template parameters so credentials are now passed via explicit CLI flags. Verified cluster creation works with the new approach.
- **Fixed operator crash loop on vmaas-dev**: Diagnosed and resolved the osac-operator failing to start due to missing RBAC permissions for the PublicIP resource. Operator is now running with all controllers syncing.
- **Fixed tenant assignment bug**: Corrected AuthConfig so that only the template-publisher service account receives multi-tenant access, unblocking cluster creation.
- **Fixed Ansible role resolution failure** ([osac-aap#282](https://github.com/osac-project/osac-aap/pull/282)): AAP jobs were failing because a role reference used a short name instead of its fully-qualified collection name, introduced during the Netris integration ([MGMT-23420](https://issues.redhat.com/browse/MGMT-23420)). Fixed, deployed, verified, and merged.
- **Cleaned up stale ESI resources on vmaas-dev**: Deleted 5 orphaned routers that were exhausting the router quota, removed stale cluster orders and agent labels, and brought the environment to a clean state with free hardware agents available.
- **Identified ESI agent registration gap**: Discovered that certain hardware agents are not registered in ESI's Ironic inventory, blocking cluster provisioning. Found two alternative agents that are both the correct hardware type and registered in ESI.
- **Reviewed and approved [fulfillment-service#481](https://github.com/osac-project/fulfillment-service/pull/481)**: Re-reviewed the installation guide PR — all prior findings addressed, approved.
- **Reviewed and approved [osac-aap#268](https://github.com/osac-project/osac-aap/pull/268)**: Confirmed the last open item (Netris API merge-style PUT behavior) via Slack with Dan, then approved.
- **Reviewed [osac-aap#279](https://github.com/osac-project/osac-aap/pull/279)** ([MGMT-24176](https://issues.redhat.com/browse/MGMT-24176)): Reviewed the BMH-based agent import playbook, posted 3 important findings including a silent skip bug and missing job template settings.
- **Created `/slack-read` command**: Built a Claude Code command to read and summarize Slack threads directly from the CLI.

## Risks & Challenges

- **Cluster deletion blocked by DNS permissions**: The delete flow fails at the DNS cleanup step because the IAM user is missing a required Route 53 permission. This is a separate blocker from the role resolution fix and needs to be resolved before deletions work end-to-end.
- **Orphaned ESI resources after force-deletes**: Removing finalizers to unstick cluster orders skipped the normal AAP cleanup, leaving routers and possibly other resources orphaned in ESI that need manual cleanup.
- **Demo cluster not yet operational**: Multiple issues were resolved today but the demo cluster still hasn't reached a ready state — the remaining step is to reassign hardware agents that are actually registered in ESI and retry.

## Key Effort

Stabilizing the vmaas-dev CaaS demo environment by fixing a chain of blocking issues (operator crash, tenant misconfiguration, Ansible role resolution, router quota exhaustion, and agent registration gaps) to enable end-to-end cluster creation.
