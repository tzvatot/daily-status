# Daily Status - 2026-06-16

## Accomplishments
- Investigated cluster provisioning failures on test-infra-cluster-caas. Root cause: the catalog item has `pull_secret` as an editable field with no default, and none was provided at creation time, causing the AAP job to fail validation. After providing a pull secret, the AAP job progressed but the cluster had already entered a terminal FAILED state from the earlier error, preventing further status updates.
- Recreated a fresh test cluster with the correct pull secret. The cluster is now provisioning (AAP job running), pending completion.
- Created [OSAC-1552](https://redhat.atlassian.net/browse/OSAC-1552) to track a validation gap where the server silently accepts cluster creation without required editable fields. Linked [OSAC-1416](https://redhat.atlassian.net/browse/OSAC-1416) as a prerequisite.
- Reviewed [OSAC-1415](https://redhat.atlassian.net/browse/OSAC-1415) (cluster upgrade feature gaps) and posted a design comment covering six open areas: RESTful sub-resource model, cancellation, scheduling, maintenance windows, notifications, and version catalog sync strategy.
- Reviewed CodeRabbit comments on [osac-test-infra#44](https://github.com/osac-project/osac-test-infra/pull/44) (E2E tests for catalog item lifecycle) — all comments were already addressed; CodeRabbit approved.

## Risks & Challenges
- The controller treats FAILED as a terminal state and stops syncing status updates, which means a cluster that fails early cannot recover even if the underlying AAP job eventually succeeds. This caused orphaned jobs and required full cluster recreation.
- Host types list returns empty via the public API even though hubs are registered and ClusterOrders are being created — needs further investigation.

## Key Effort
Debugging and resolving cluster provisioning failures on the test infrastructure, identifying a missing required field validation gap, and driving design discussions for the cluster upgrade feature.
