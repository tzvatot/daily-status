# Daily Status - 2026-06-16

## Accomplishments
- Investigated cluster provisioning failures on test-infra-cluster-caas. Root cause: the catalog item has `pull_secret` as an editable field with no default, and it wasn't provided at creation time, causing the AAP job to fail validation. Providing the pull secret resolved the validation error, but the cluster had already transitioned to a terminal FAILED state, preventing further status syncing.
- Recreated `etabak-cluster` with the correct pull secret. The cluster is now provisioning (AAP job running, ClusterOrder in Progressing state). Waiting for provisioning to complete and reach Ready state.
- Created [OSAC-1552](https://redhat.atlassian.net/browse/OSAC-1552) to track a validation gap where the server silently accepts cluster creation without required editable fields being provided. Linked [OSAC-1416](https://redhat.atlassian.net/browse/OSAC-1416) as a prerequisite for enforcement.

## Risks & Challenges
- Discovered that once a cluster reaches the FAILED state, the controller treats it as terminal and stops syncing status updates. This means even if the underlying AAP job recovers, the cluster will remain stuck in FAILED. This caused orphaned AAP jobs during debugging.
- Host types list returns empty via the public API, even though hubs are registered and ClusterOrders are being created successfully — may indicate an API or data surfacing issue.

## Key Effort
Debugging and resolving cluster provisioning failures on the test-infra environment, identifying a missing pull secret as the root cause and a terminal FAILED state handling issue in the controller.
