# Daily Status - 2026-06-16

## Accomplishments
- Investigated cluster provisioning failures on test-infra-cluster-caas. Root cause was a missing pull secret — the catalog item had it as an editable field with no default, and none was provided. After supplying the pull secret, the AAP job passed validation but the cluster still failed because the controller treats FAILED as a terminal state, preventing further status sync.
- Recreated the test cluster with the correct pull secret; cluster is now progressing and awaiting provisioning completion.
- Created [OSAC-1552](https://redhat.atlassian.net/browse/OSAC-1552) to track a validation gap where the server silently accepts cluster creation without required editable fields. Linked [OSAC-1416](https://redhat.atlassian.net/browse/OSAC-1416) as a prerequisite.
- Reviewed [OSAC-1415](https://redhat.atlassian.net/browse/OSAC-1415) (cluster upgrade feature gaps) and posted a comment outlining six open design areas for the enhancement proposal: RESTful sub-resource model, cancellation, scheduling, maintenance windows, notifications, and ACM version catalog sync strategy.
- Reviewed CodeRabbit comments on [osac-test-infra#44](https://github.com/osac-project/osac-test-infra/pull/44) (E2E tests for catalog item lifecycle) — all comments were already addressed and the review status is approved.

## Risks & Challenges
- The controller's treatment of FAILED as a terminal state means any transient failure during provisioning is unrecoverable without deleting and recreating the cluster.
- Host types list returns empty via the public API even though hubs are registered and ClusterOrders are being created — needs further investigation.

## Key Effort
Debugged and resolved cluster provisioning failures on the test infrastructure, identifying a missing pull secret and a terminal-state handling issue in the controller.
