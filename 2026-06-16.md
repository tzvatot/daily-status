# Daily Status - 2026-06-16

## Accomplishments
- Investigated cluster provisioning failures on test-infra-cluster-caas — root cause was a missing pull secret for a required editable field with no default value. After providing the pull secret, the provisioning progressed past validation but hit a separate issue where the controller treats FAILED as a terminal state, preventing status recovery even if the underlying job continues.
- Recreated a fresh test cluster with the pull secret included; cluster is currently progressing through provisioning.
- Created [OSAC-1552](https://redhat.atlassian.net/browse/OSAC-1552) to track a validation gap where the server silently accepts cluster creation without required editable fields. Linked it as blocked by [OSAC-1416](https://redhat.atlassian.net/browse/OSAC-1416) since field definition enforcement is a prerequisite.
- Reviewed [OSAC-1415](https://redhat.atlassian.net/browse/OSAC-1415) (cluster upgrade feature gaps) and posted a comment outlining six open design areas for the enhancement proposal: RESTful sub-resource model, cancellation, scheduling, maintenance windows, notifications, and ACM version catalog sync strategy.
- Reviewed CodeRabbit comments on [osac-test-infra#44](https://github.com/osac-project/osac-test-infra/pull/44) (E2E tests for catalog item lifecycle) — all comments were already addressed; CodeRabbit approved.

## Risks & Challenges
- The controller treats FAILED as a terminal state, so clusters that fail transiently cannot recover even if the underlying job eventually succeeds. This caused orphaned jobs and required manual cleanup and re-creation.
- Test cluster provisioning is still in progress and not yet verified as successful.

## Key Effort
Debugging and resolving cluster provisioning failures on the test infrastructure, uncovering both a missing-field validation gap and a terminal-state recovery issue in the controller.
