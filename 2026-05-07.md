# Daily Status - 2026-05-07

## Accomplishments
- **Resolved OAuth integration issue with fulfillment-controller**: Fixed the Authorino AuthConfig issuer URL that was pointing to the wrong Keycloak port, which caused token validation timeouts. OAuth authentication now works correctly and the API returns cluster data.
- **Fixed tenant assignment in JWT authorization**: Corrected the AuthConfig tenant expression so that JWT-authenticated requests receive valid tenant assignments, resolving "tenant can't be assigned" errors during controller reconciliation.
- **Updated ClusterOrder CRD to include required fields**: Applied the latest CRD from [osac-operator](https://github.com/osac-project/osac-operator) so that cluster orders include all necessary provisioning fields (pull secret, SSH key, release image) that were previously being silently dropped.
- **Cleaned up stale cluster data**: Purged orphaned clusters from the database that were left behind by force-deleted orders, and reset cluster status to allow the controller to proceed with new orders.
- **Validated end-to-end cluster provisioning flow**: Successfully triggered the full AAP provisioning pipeline — L2/L3 networking, agent registration, DNS, HostedCluster creation, and MetalLB ingress all passed. The job failed late in bootstrap due to an infrastructure-level MTU probe timeout, confirming all application-layer fixes are working correctly.

## Risks & Challenges
- Cluster bootstrap fails with an MTU probe timeout during network operator initialization. This appears to be an ESI bare-metal network/VLAN configuration issue, not an application-level problem. Investigation is needed to determine the correct MTU settings for the environment.

## Key Effort
Continued debugging and fixing the fulfillment-controller's OAuth and Authorino integration, culminating in a successful end-to-end provisioning run that validated all application-layer fixes.
