# Daily Status - 2026-05-07

## Accomplishments
- **Resolved OAuth integration issue with fulfillment controller** — Fixed the Authorino AuthConfig issuer URL that was pointing to the wrong port, which caused Authorino to time out when connecting to the Keycloak JWKS endpoint. OAuth tokens now work correctly and the API returns clusters successfully.
- **Fixed tenant assignment in JWT authentication** — Corrected the AuthConfig tenant expression so that JWT-authenticated requests receive valid tenant values, resolving the "tenant can't be assigned" error during cluster updates.
- **Updated ClusterOrder CRD to include required fields** — Applied the latest CRD from [osac-operator](https://github.com/osac-project/osac-operator) so that cluster orders now correctly carry pull secret and SSH public key data, which were previously being silently dropped by Kubernetes.
- **Cleaned up stale cluster data** — Purged orphaned clusters from the database that were left behind by force-deleted orders, and reset cluster status to allow the controller to proceed with new orders.
- **Validated end-to-end cluster creation flow** — Successfully triggered the full AAP provisioning pipeline, which passed L2/L3 networking, agent registration, floating IP, DNS, and HostedCluster creation stages before encountering an infrastructure-level MTU issue unrelated to application code.

## Risks & Challenges
- AAP provisioning job failed after ~58 minutes due to an MTU probe timeout in the network operator — this is an ESI bare-metal network configuration issue, not an application-level problem. Investigation into the VLAN/MTU configuration is needed before retrying cluster creation.

## Key Effort
Continued debugging and fixing the fulfillment controller's OAuth and Authorino integration, reaching a fully working end-to-end flow that is now blocked only by an infrastructure networking issue.
