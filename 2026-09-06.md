# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent ClusterOrder feedback condition mapping. PR received LGTM and approval, all CI checks passed, and it was merged.
- Validated the PROGRESSING feedback behavior on a real OSAC deployment (caas-ci environment) across four test scenarios:
  - **T1 & T2:** Confirmed correct furthest-stage derivation of the PROGRESSING condition using manually patched ClusterOrder conditions.
  - **T3:** Validated full lifecycle PROGRESSING advancement through a real HyperShift control plane boot — watched the condition advance from `ControlPlaneCreated` through `ControlPlaneAvailable`, with the cluster reaching READY.
  - **T4:** Confirmed order-independence — the feedback controller correctly derived the furthest stage regardless of the order conditions were set by the operator.
- Stood up a complete OSAC test environment on a caas-ci host, including deploying Metal3/Ironic, registering a bare-metal agent, and configuring the AAP automation controller to work on a single-node OpenShift cluster.
- Investigated and resolved six deployment blockers during environment setup:
  - Metal3/Ironic not deployed on a `None`-platform cluster — created the required Provisioning resource.
  - Bare-metal host registration failing due to an HTTPS/HTTP protocol mismatch with the BMC emulator.
  - AAP job failing because the pull secret was missing and the service account lacked RBAC to read it.
  - AAP job failing because the network backend defaulted to an OpenStack-based path not available in the CI environment — switched to the CI-appropriate network backend.
  - Agent selection failing because the agent label used a name string instead of the expected host type identifier.
  - Etcd unable to form quorum because the control plane was configured for high availability on a single-node cluster — switched to single-replica mode.

## Risks & Challenges

- The `lifecycle-v3` test cluster has AAP post-install jobs still running and has not yet reached full READY state.
- The CI cluster template does not default to the correct network backend or single-replica control plane settings for single-node environments — these required manual overrides. This configuration gap is worth raising with the team.
