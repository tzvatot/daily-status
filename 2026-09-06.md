# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441), implementing order-independent PROGRESSING condition derivation for ClusterOrder feedback. PR passed all CI checks and was approved and merged.
- Validated the PROGRESSING feature on a real OSAC deployment (caas-ci environment) by running four end-to-end tests confirming the feedback controller correctly derives the furthest lifecycle stage as the cluster progresses through control plane creation and availability.
- Stood up and configured a full OSAC test environment on a bare-metal host, including deploying Metal3/Ironic, registering a bare-metal worker agent, and installing the OSAC CLI.
- Debugged and resolved six deployment blockers during validation:
  - Enabled Metal3/Ironic on a platform-None SNO cluster by creating the missing Provisioning resource.
  - Fixed bare-metal host registration by switching the BMC address from HTTPS to HTTP to match the virtual BMC emulator.
  - Created the missing pull-secret credential and granted the AAP controller RBAC access to read it.
  - Switched the network backend to the CI-compatible backend that works without OpenStack.
  - Fixed agent selection by aligning the agent's resource class label with the expected host type identifier.
  - Fixed etcd quorum failure on a single-node cluster by switching the controller availability policy to single-replica mode.
- Completed a full lifecycle validation (T3 test) confirming the PROGRESSING condition correctly advances through `ControlPlaneCreated` → `ControlPlaneAvailable`, with the cluster reaching READY state and control plane fully operational.

## Risks & Challenges

- The test cluster (`lifecycle-v3`) still has AAP post-install jobs running and has not yet reached full READY state — monitoring is needed.
- The CI cluster template does not default to the correct network backend or single-replica etcd policy for single-node environments — these had to be overridden manually. This is a configuration gap worth flagging to the team.

## Key Effort

Merged and validated the order-independent ClusterOrder PROGRESSING condition feature ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)) on a real OSAC deployment, resolving multiple environment blockers along the way.
