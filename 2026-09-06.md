# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent cluster order feedback condition mapping. PR passed all CI checks (unit, integration, e2e across caas/bmaas/vmaas, linting, CodeQL) and was approved and merged.
- Validated the merged changes on a real OSAC deployment (caas-ci environment) by running four progressive tests:
  - **T1/T2**: Confirmed the feedback controller correctly derives the furthest provisioning stage from cluster order conditions, even when conditions arrive in arbitrary order.
  - **T3**: Validated a full cluster lifecycle — watched the progressing condition advance through real control plane boot stages (ControlPlaneCreated → ControlPlaneAvailable), with the control plane fully coming up and all conditions reporting True.
  - **T4**: Confirmed order-independence in a real deployment where the operator sets conditions asynchronously as it observes Kubernetes resources.
- Resolved six infrastructure blockers encountered during real-deployment validation:
  - Deployed Metal3/Ironic on a platform-None SNO cluster by creating the missing Provisioning resource.
  - Fixed bare-metal host registration by correcting the BMC address scheme from HTTPS to HTTP to match the virtual BMC emulator.
  - Fixed AAP job authentication by creating the required pull secret and granting the AAP service account appropriate RBAC access.
  - Configured the CI-appropriate network backend to bypass OpenStack dependencies not present in the test environment.
  - Relabeled the agent with the correct host type identifier so agent selection could match it.
  - Switched the etcd availability policy to single-replica mode so the control plane could form quorum on a single-node cluster.
- Registered and approved a bare-metal worker agent in the test environment, enabling end-to-end hosted cluster provisioning.

## Risks & Challenges

- The test cluster (`lifecycle-v3`) still has AAP post-install jobs running and has not yet reached full READY state — monitoring is needed.
- The CI cluster template does not configure the network backend or etcd availability policy correctly for single-node environments by default — these had to be overridden manually. This is a template configuration gap worth flagging to the team.

## Key Effort

Merged and validated [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441)'s order-independent feedback condition mapping on a real OSAC deployment, resolving multiple infrastructure blockers to complete end-to-end lifecycle testing through control plane availability.
