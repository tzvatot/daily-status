# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent cluster feedback condition mapping. PR was approved, all CI checks passed, and it merged successfully.
- Validated the PROGRESSING feedback feature on a real OSAC deployment (caas-ci environment) across four test scenarios:
  - **T1 & T2:** Verified correct furthest-stage derivation of PROGRESSING status using manually patched conditions on the deployed PR image.
  - **T3 (full lifecycle):** Watched PROGRESSING condition advance through a real HyperShift control plane boot — from `ControlPlaneCreated` through `ControlPlaneAvailable` — confirming the feature works end-to-end on a live cluster.
  - **T4 (order-independence):** Confirmed the feedback controller correctly handles conditions arriving in any order, as happens naturally in the real deployment.
- Set up the caas-ci test environment end-to-end: deployed OSAC on an OCP SNO cluster, registered a bare-metal worker agent via Metal3/Ironic, and configured the AAP automation pipeline.
- Resolved six environment blockers during validation:
  - Deployed Metal3/Ironic by creating the missing Provisioning resource (platform type `None` doesn't auto-deploy it).
  - Fixed bare-metal host registration by switching the BMC address to HTTP (sushy-emulator doesn't support TLS).
  - Created the missing pull-secret credentials and granted the AAP service account the necessary RBAC permissions.
  - Switched the network backend to the CI-compatible one that works without OpenStack, since the test environment has no OpenStack.
  - Fixed agent selection by ensuring the agent label matched the host type identifier the operator expects.
  - Switched the etcd availability policy to single-replica mode so the control plane can run on a single-node cluster.
