# Daily Status - 2026-09-06

## Accomplishments
- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent feedback condition mapping for ClusterOrder provisioning status. PR was approved, all CI checks passed, and it merged successfully.
- Validated the merged changes on a real OSAC caas-ci deployment (not just unit/e2e tests). Ran four test scenarios (T1–T4) confirming that the PROGRESSING condition correctly derives the furthest provisioning stage from ClusterOrder conditions, including a full lifecycle test watching a real HyperShift control plane boot through `ControlPlaneCreated` → `ControlPlaneAvailable` → `READY`.
- Resolved six infrastructure blockers during the real deployment validation:
  - Deployed Metal3/Ironic by creating the missing Provisioning CR (needed on platform=None SNO clusters)
  - Fixed BareMetalHost registration by correcting the BMC address scheme to use HTTP instead of HTTPS for sushy-emulator
  - Created the missing pull-secret and SSH key credentials and added the necessary RBAC for the AAP controller
  - Configured the CI-appropriate network backend to bypass OpenStack/ESI (not available in this environment)
  - Relabeled the agent to match by host type identifier instead of name string
  - Set etcd to single-replica mode so the HyperShift control plane can run on a single-node cluster
- Submitted draft [osac#767](https://github.com/osac-project/osac/pull/767) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 — adds provisioning sub-stage reason derivation (e.g., PreparingInfrastructure, ControlPlaneStarting, WorkersJoining) based on HyperShift conditions, with full test coverage. Awaiting CI and reviews.
