# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent ClusterOrder feedback condition mapping. All CI checks passed, PR was approved and merged.
- Validated the merged change on a real caas-ci deployment (host karim04). Ran four test scenarios confirming that the PROGRESSING condition correctly derives the furthest provisioning stage regardless of the order conditions are set, including a full lifecycle test where the condition advanced through control plane creation to control plane availability during an actual HyperShift boot.
- Stood up and configured the real OSAC deployment environment end-to-end, resolving six infrastructure blockers: deploying Metal3/Ironic on a platform-None SNO, fixing BMH registration to use HTTP for the virtual BMC, creating missing cluster credentials and RBAC for AAP, switching the network backend to bypass OpenStack (not available in this environment), and setting etcd to single-replica mode for SNO compatibility.
- Registered a bare-metal worker agent through the full lifecycle: VM creation, BMH provisioning, discovery ISO boot, and agent approval.
- Implemented sub-stage reason derivation for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02 — the feedback controller now reports finer-grained provisioning sub-stages (e.g., preparing infrastructure, control plane starting, workers joining) by reading HyperShift conditions. Submitted draft [osac#767](https://github.com/osac-project/osac/pull/767) for review, including new tests and a fix for a critical bug where the progressing status was incorrectly overwritten when the cluster reached ready state.
