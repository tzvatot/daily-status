# Daily Status - 2026-09-06

## Accomplishments

- Merged [osac#646](https://github.com/osac-project/osac/pull/646) for [OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) — order-independent PROGRESSING condition derivation for ClusterOrder feedback. All CI checks passed, PR was approved and merged.
- Validated the merged changes on a real caas-ci deployment (karim04 host) by running four end-to-end test scenarios (T1–T4) that confirmed the PROGRESSING condition correctly advances through provisioning stages (Accepted → ControlPlaneCreated → ControlPlaneAvailable) on a live OSAC environment with an actual HyperShift control plane boot.
- Resolved six deployment blockers during validation: missing Provisioning CR preventing Ironic/Metal3 from deploying, BMH registration failing due to HTTPS vs HTTP mismatch with the BMC emulator, missing pull secret and RBAC for the AAP service account, AAP jobs defaulting to an OpenStack network backend unavailable in the CI environment, agent label mismatch preventing worker selection, and etcd requiring single-replica mode on a single-node cluster.
- Set up a bare-metal worker VM with agent registration, BMC emulation, and host type configuration to enable full cluster lifecycle testing on the CI environment.
- Implemented sub-stage reason derivation ([OSAC-4441](https://redhat.atlassian.net/browse/OSAC-4441) Story 1.02) — the feedback controller now reports finer-grained provisioning sub-stages based on HyperShift control plane conditions. Submitted draft [osac#767](https://github.com/osac-project/osac/pull/767) for review, awaiting CI and reviews.
