# Daily Status - 2026-08-11

## Accomplishments
- Continued design discussions on [OSAC-3538](https://redhat.atlassian.net/browse/OSAC-3538) (Catalog Items v2) — agreed that a separate lock-scope mechanism is unnecessary, simplifying the overall design
- Clarified the editability pattern for cluster fields: version should be editable with a constrained allowed value rather than fully locked, to avoid blocking upgrades
- Posted [feedback](https://github.com/osac-project/enhancement-proposals/pull/201#discussion_r3756287803) on the PRD update in [EP#201](https://github.com/osac-project/enhancement-proposals/pull/201): fields requiring day-2 mutation (e.g., version, node pool sizing) should not be lockable, and each catalog item should define which fields must remain editable
