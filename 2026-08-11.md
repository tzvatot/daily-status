# Daily Status - 2026-08-11

## Accomplishments
- Continued design work on [OSAC-3538](https://redhat.atlassian.net/browse/OSAC-3538) (Catalog Items v2): resolved open questions around field lockability vs. editability constraints, clarifying that certain fields (like version) must remain editable to avoid blocking day-2 operations such as upgrades
- Replied to Avishay's PRD update ([EP#201](https://github.com/osac-project/enhancement-proposals/pull/201)) with guidance that the server should reject locking fields that require day-2 mutation, and that each catalog item must define which fields are always editable
- Updated the v1 design document to cover update-time governance enforcement, per-field lockability validation, and catalog item update constraints
- Self-reviewed and fixed issues in the design document (example inconsistencies, default value ambiguity, referential integrity gaps, missing test cases)
- Published the design as a draft PR ([EP#202](https://github.com/osac-project/enhancement-proposals/pull/202)), awaiting review
- Posted a status update to #osac-eng on PRD and design progress

## Risks & Challenges

- Design review on [EP#202](https://github.com/osac-project/enhancement-proposals/pull/202) not yet started

Advancing the Catalog Items v2 design for [OSAC-3538](https://redhat.atlassian.net/browse/OSAC-3538), resolving open governance questions and publishing the draft design for review.
